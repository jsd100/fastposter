# FastPoster 编辑体验、内置字体与上传兼容设计

日期：2026-11-03。状态：待用户批准完整方案。依据：本次对话与 `docs/analysis/2026-11-03-ui-font-image-analysis.md`。

## 已确认的需求

- 用户制作三四句短句、歌词海报，需要更丰富的字体；已选择内置覆盖电脑常见风格的路线，同时覆盖文艺柔和与醒目标题。
- 搜索框焦点符合当前绿色主题，Select 箭头左右留白平衡，错误通知统一为 Message/Toast。
- 编辑设置中的字号、行高、字距、数值文字效果采用左右减/加、中间输入的控件。
- 合法图片即使扩展名与真实格式不一致，也应能够上传。
- 保留当前清新风格、整体页面布局与既有数据/导出能力。

下文的首批字体名单、具体间距、通知时长及分组方式由本次设计提出，尚未作为用户已决定的细节。项目包含前后端与字体资源，完整方案批准后制定实施计划。

## 范围与边界

在现有 Base UI 1.9.0、CSS Modules、共享 `@fastposter/ui` 上完成；不另引入整套组件库。覆盖用户站、共享编辑器与使用这些控件的后台；新字体对用户作品和后台模板编辑器均可用。

不增加本机字体枚举、私有字体自动上传、任意系统字体 fallback、复杂排版预设、主题切换。服务器、浏览器、模板包共用同一版本的托管字体。保留后台已有字体上传/发布能力，历史文档中的字体 assetId/version 不重命名。

前一轮修复仍在当前工作树，修改前应核对状态；不得覆盖 NumberField 的有效修复、测试或其他任务改动。

## 1. 共享焦点与选择器留白

所有 TextInput/Textarea 变体，包括 bare，都附加不决定外框尺寸的焦点基础类。使用现有 `--fp-focus-line` 和 `--fp-focus-shadow`，移除露出的原生蓝色 outline，同时保留清晰的键盘焦点。审计搜索、普通表单、后台搜索、数字输入组及弹窗初始聚焦。

Select 取消 Value 的额外 4px 缩进与 Icon 的 -6px 边距。触发器统一持有逻辑 padding：普通 10px、compact 8px；页面允许调整宽度与布局，不再叠加图标偏移。图标保持固定尺寸，长文本不挤压它。保留菜单整行点击和触屏选项 44px 目标。

更新旧测试中“箭头距右边框不超过 4px”的断言：新的目标是左右视觉留白平衡，容许字形本身约 2px 的测量误差；不用旧错误指标反向限制实现。

## 2. 统一 Message/Toast

在 UI 包封装 Base UI Toast Provider、视口与通知入口。用户站和后台分别挂载；不在 Status 的 render 中发通知。错误通过状态转移/操作结果触发，避免请求拦截器和消费方重复报错。

- 视觉：暖白底、深绿正文、淡绿边框，错误使用既有浅赤陶色与图标；桌面顶部居中，手机在安全区内，至多同时显示 3 条。
- 成功/普通操作提示默认 4 秒，操作失败默认 6 秒，支持关闭、悬停/聚焦暂停。持续故障可常驻，恢复后更新或关闭。
- 查询错误按资源和错误身份去重；同一失败不因重绘或 500ms 字形检测重复弹出，明确的再次操作可以更新提示。
- 字段错误保留 label/error 的关联与定位，Toast 可概括；保存/离线/冲突的持续状态及必要动作仍保留，不能把“为什么不能导出”变成已消失的通知。
- 缺字、加载失败等持续阻断使用可更新通知，并在相关字段/保存状态处留可查原因。版本冲突仍由现有冲突对话框承载。
- 不抢编辑器焦点；通知和重试动作必须在 Dialog/BottomSheet 打开时仍可见、可被辅助技术发现，并验证模态可访问树和层级。切换账户/退出时清除旧账户通知。

迁移现有各错误 Status 的消费场景，保持重试和恢复能力；普通加载/空状态无需变成 Toast。

## 3. 首批内置字体与分发

首批建议 6 个家族（已有 2 个 + 新增 4 个），不是声称这些就是 Windows/macOS 系统字库。中文装饰字体不能承诺覆盖所有生僻字，仍按实际文本检查。

| 家族 | 角色 | 纳入字重 |
| --- | --- | --- |
| Noto Sans SC（保留现有思源黑体名称） | 通用黑体、醒目粗标题 | 保留 400/700，增加实际字库支持的 900 |
| Noto Serif SC | 宋体风格、歌词与诗句，也提供粗标题 | 400/700/900 |
| LXGW WenKai / 霞鹜文楷 | 楷书、手写感、柔和短句 | 正常体 400；不合成粗体/斜体 |
| ZCOOL KuaiLe / 站酷快乐体 | 活泼、有个性的标题 | 正常体 400 |
| ZCOOL XiaoWei / 站酷小薇体 | 装饰风格、文艺标题 | 正常体 400 |
| Inter | 英文歌词、数字与英文标题 | 保留 400/700，明确标为西文 |

实施时从官方来源获取完整字体与相应许可证，固定来源版本、文件 SHA-256、文件名、家族、实际支持字重。没有实际字形的样式不可声明。优先使用未改字形的官方字库，不为缩小文件删掉用户可能输入的汉字。

利用已有 manifest/bootstrap 机制注册新家族，升级已有安装时幂等添加而不依赖清库；不覆盖历史资产。验证当前 20MiB 上传/30MiB 解码限制和实际文件大小：内置资源使用现有受控 bootstrap 路径，不放宽用户上传限额；若指定完整字库无法通过可信加载限制，应报告具体文件与限制，在保留这 6 个家族和字符覆盖的前提下选择官方等价打包格式，不静默换字体或削减覆盖。

当前 ListFonts 按字面 LIMIT 100，排序可能使家族被截断。本轮保持该返回上限，让内置字面优先进入结果，其余位置继续展示后台发布字体；下拉搜索在这些候选内进行，不新增字体市场或分页 API。旧作品字体仍按资产版本解析，即使不在本次已发布候选中也能继续渲染。

## 4. 字体选择与缺字预检

字体选择升级为可搜索 Combobox；中文优先，家族按通用/文艺/标题/西文显示适用标签。保留现有字体名字的兼容显示，新增字体用明确中文名，不把风格近似称为微软雅黑、苹方等具体字体。

菜单不一次下载所有 CJK 字库；默认标签用 UI 字体，高亮候选在独立预览区域按需展示当前短句或预设样例。缓存/合并同一字体版本的加载请求，失败后允许重试。仅预览不改文档，不写入字体引用、不产生撤销历史。

应用范围由当前编辑状态确定：有选区只改选区；编辑模式空选区影响后续输入；未编辑时改整块文字。候选字重优先保留当前可用字重，否则使用该家族 400，并清理目标范围内不支持的粗/斜体 mark，用一次提示说明实际样式调整，不让旧 mark 导致后端报“缺少字重”。范围外内容与 marks 不变。

选中候选后先加载字体并验证当前目标文本/目标样式，成功后才原子应用字体引用和排版变更，一次撤销恢复此次换字体。过程中保持 Tiptap 选区，新的选择/文档/账号切换使旧请求失效；不能把迟到的校验结果应用到另一选区。

预检可复用现有 CheckFonts：构造只含目标文本/样式、必要字体引用、且符合现有文档结构的候选文档，不改变真实文档。不得因作品其他范围原有缺字而错误拒绝当前范围的修复。缓存以字体版本、目标文本、有效样式组合为键。实施者可改为等价的专用覆盖接口，但不得弱化服务端校验或将字体解析移到无关组件。

明确缺字候选显示缺失字符，阻止应用并保持原排版，给出中文字体替代入口。无法校验/无法加载时报告原因并允许重试。空光标没有未来文本可检验，允许设置插入字体；之后输入超出覆盖的文字仍由整文档检测与导出校验提示，不虚假承诺任何未来字符均可用。

保留当前整文档检测及 export worker 的最终检查；已有不兼容文档仍可编辑、换字体修复。用户只选中英文时可以使用 Inter，不为整段中文静默使用系统 fallback。

## 5. 左右步进数字控件

在已有 NumberField 上增加显式 stepper 变体，使用 Base UI Group/Decrement/Input/Increment。用户指定的编辑设置全部启用，普通表单输入不强制更换外观。颜色输入保持现有颜色控件。

| 设置 | 显示 | 步长 | 范围 |
| --- | --- | --- | --- |
| 字号 | px | 1 | 1–4096 |
| 行高 | 倍 | 0.1 | 0.5–5 |
| 字距 | px | 1 | -100–1000 |
| 透明度 | % | 5 | 0–100；内部仍为 0–1 |
| 内边距/描边/阴影模糊/偏移 | px | 1 | 保留各自现有范围与动态上限；偏移允许负数 |

展示单位不写入数值模型。动态 padding 上限可能不是整数，不通过步进越界；在上下限禁用对应按钮。混合字号显示“混合”；首次 +/- 以目标范围起始文字的有效字号为基准加/减 1，再应用目标范围，不随意使用 0 作为混合字号。

点击单次 +/- 为一次可撤销操作，按住连续步进的一次按住/松开视为一次交互，继承编辑器事务机制；不产生表单提交，不丢选区，不误触画布。保持前轮已修复的草稿/Enter/Escape、真实键入、IME、方向键边界与外部撤销同步。

桌面保持侧栏视觉密度；触屏按钮有效目标至少 44px。输入组空间不足时将并排字段变成单列，不压缩中间数值区域。主要页面布局与画布位置不作无关调整。

## 6. 图片格式按内容识别

支持现有静态 PNG/JPEG/WebP。通过 Probe/解码后，扩展名缺失或不符时按真实格式纠正文件名，再进入现有标准化流程；不强制按上传名称进行有损转码。文件名的展示与下载如需区分，可在现有 metadata 留原始名称；实际响应 MIME/下载后缀与内容匹配。

用户提供的 `.jpg` 实为 1152×2048 PNG，是应成功的验收样本。保留文件名路径/控制字符清洗、原文件尺寸/字节上限、动画限制、结构与解码检查；任意文本假冒图片或损坏数据仍拒绝。不顺带开放其他图像格式、动态图片或取消现有限额。

修改现有“合法 PNG 命名 jpg 应 422”的测试预期，同时保留伪造/损坏内容拒绝；覆盖用户上传背景、后台上传背景、作品预览和最终导出。

## 验收要求

1. 同条件桌面/移动视口对照截图：主题、布局、焦点、Select 留白、数字组和 Toast；允许本设计明确的控件变化。
2. bare 搜索、后台输入、自动聚焦、键盘 Tab 均无蓝色默认轮廓；Select 文字和箭头留白平衡，整行可点、长文本无溢出。
3. Toast 在弹窗内可见/可访问，错误去重、重试、关闭和持续状态正确；不抢焦点，不跨账户残留。
4. 六个家族在新安装和已有数据升级后均可发现。真实字面支持的字重正确；换中文/西文字体、混合选区、字体加载失败、迟到响应、已有缺字文档、换字体撤销均有用例。
5. 字体预览与导出用相同资产版本；验证中英文三四句短文、标点、换行、字重与样式一致。测试按需加载和缓存，不能只验证字体名出现在列表中。
6. +/- 单击、长按、边界、负数、小数、透明度百分比、混合字号、选区保留和撤销有真实浏览器用例；保留前一轮数字草稿回归。
7. 合法错后缀图片成功且 MIME/尺寸/规范化内容正确；伪造、损坏、过大等仍拒绝；用小型 fixture 自动化并人工核验用户提供样本。
8. 执行契约检查（若改 DTO/IDL）、typecheck、单测、强制构建、相关 Go 测试和完整功能 E2E。记录实际字体文件体积与应用包体变化；浏览器模拟手机不宣称为真机验证。

## 实施者可决定的细节

模块文件拆分、内部 hook 名称、通知去重键结构和缓存实现可自行确定。前述首批家族、字段范围、事务语义、样式与上传规则不得自行缩减；若需改变应更新方案。未在本轮承诺更多语言字库、emoji 字体或全部生僻字覆盖。
