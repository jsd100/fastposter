# 编辑器与画廊功能设计

2026-11-16 · 背景图放大范围已确认 · 代码基线 `10bac7b`

[需求分析与源码证据](../../analysis/2026-11-13-editor-gallery-features-analysis.md)

用户确认了九宫格可开关、连续字重的目标范围 100–700，以及可用于局部选区的线性和径向渐变。同一施加范围跨行时保持一个连续渐变。预设、卡片高亮、背景放大和回收站布局沿用用户提出的目标。本文给出其余交互默认值和实施边界，作为待评审的设计建议。

## 1. 画布九宫格

- 在画布缩放控件附近放置带可见标签的 antd `Switch`「九宫格」。默认关闭。开启后始终在海报范围内显示，拖动前后保持一致。关闭立即隐藏。手机端和键盘均可操作。
- 显示两横两竖，位于海报宽、高的三分之一和三分之二处。线宽约一个屏幕 CSS 像素，采用静态、低干扰且在深浅背景上可辨认的线条。文字仍然自由拖动。
- 用户站和管理端模板编辑器复用控件。按当前浏览器、站点和登录账号记住选项，切换作品、刷新后恢复，切换账号时重新读取该账号偏好。存储不可用时保留当前会话的开关能力。
- 在共享编辑器 `Stage` 内使用与选择手柄一致的舞台坐标。平移和缩放后始终贴合海报内容区域，层级低于选择框，不拦截鼠标或触摸。辅助线不参与选择、布局测量、作品序列化、撤销和自动保存。

**验收**：拖动、缩放、平移、双指缩放和调整文字框时参考线准确贴合且无事件拦截。检查两站、320px 和 390px 的开关焦点与触控。切换开关前后作品修订数相同，同一修订的导出像素相同。

## 2. 阴影和描边预设

在「文字设置 → 效果」增加「预设阴影」和「预设描边」。入口与当前预设文字颜色的操作一致，选项用有文字的样例表现真实效果。现有数值和颜色控件放在各自预设下方。应用作用于当前文字块。

| 阴影预设 | 颜色 | X / Y / 模糊（海报 px） |
| --- | --- | --- |
| 无 | `#00000000` | 0 / 0 / 0 |
| 柔和投影 | `#00000073` | 2 / 3 / 6 |
| 硬边投影 | `#000000B3` | 3 / 3 / 0 |
| 发光 | `#FFFFFFCC` | 0 / 0 / 6 |

| 描边预设 | 颜色 | 宽度（海报 px） |
| --- | --- | --- |
| 无 | 保留当前调色值 | 0 |
| 亮色细描边 | `#FFFFFF` | 1 |
| 暗色细描边 | `#151515` | 1 |
| 粗描边 | `#151515` | 3 |

- 按一次预设原子更新该效果并产生一次撤销。按有效参数匹配预设，其他组合显示「自定义」。整块不透明度、文字背景和另一种效果保留。
- 启用自定义时，如果当前仍是关闭态，提供一个明确的启用入口，分别用「柔和投影」和「暗色细描边」初始化。打开控件、读入旧值、手动将透明度设到零都不自动重写。
- 沿用 `block.effects` 和 `blockCSS`。预设颜色与数值是初始设计值，由实现时在亮底和暗底校准。

**验收**：柔和投影和硬边阴影在浅底可见，发光在暗底可见。描边切换、关闭和一次撤销均有效。编辑器、缩略图和透明导出验证相同参数，渐变组合另见 §4。

## 3. 连续字重

- 可变字体使用步长 1 的滑杆和可见数值，日常范围取字体真实轴与 100–700 的交集。Noto Sans SC 和 Inter 显示 100–700，Noto Serif SC 显示 200–700。Inter 的字形覆盖规则照常生效。静态字体保留可用字重列表，只有一个档位时显示实际字重。
- 从旧文档载入 800、900 等值时显示实际值。用户主动操作滑杆后才进入常用范围。更换家族时保留新字体支持的样式和字重。超出范围时，在应用前沿用字体选择的回退提示，明确显示将使用的值。混合选区保留「混合」提示并允许设置统一值。
- 编辑态选区改选中的文字，光标态改后续输入，选择态修改文字块。显式字重覆盖同一修改范围的粗体标记，粗体按钮继续表示原有 700 字重行为。一次拖动一条历史记录。
- 资源版本与字体样式决定真实能力。按 `assetId + version` 获取和缓存可变范围，浏览器通过 `FontRegistry` 注册范围，Go 在字体覆盖检查和导出链使用相同的选择规则。相同资产的不同版本在同一个浏览器页面预览时分别解析和注册，避免一个版本的轴范围或字体数据覆盖另一个版本。先尝试同家族同样式的精确字重，再使用轴真实覆盖请求值的同样式可变文件。保留字体引用、资源权限、版本完整性和字符覆盖检查。字体引用用于标识真实资源，一个资源可承载多个文字字重。
- 维持现有文档的 `fontWeight` 100–900 合法范围。先核对导出入队的 `exports/service.go`、worker、渲染器和 `fontfile.CheckDocument` 的精确匹配，再调整一致规则。字体能力由可信资源字节或经实际文件确认的元数据提供。实现可选择传递可信元数据或复用解析，通路选择写入实施计划。

**验收**：作品只引用标称 400 的可变字体版本时，100、250、400、700 都能改变实际字形，保存重开、字体检查、入队及最终 PNG 均成功。覆盖静态字体、历史 900、缺失斜体、过期或不可读文件、混合选区和两次连续编辑。静态字体的字重错误继续明确返回。

## 4. 文字渐变

### 4.1 操作与显示

- 在「文字颜色」提供纯色、线性和径向三种类型。线性支持方向角度，径向支持可移动的圆心。渐变可设置 2–8 个有序色标，每个色标可改位置、颜色和透明度。位置允许相等以表达硬边，线性方向沿用 CSS 角度定义，中心按施加范围的宽高百分比表示。
- 「预设文字颜色」保留现有纯色预设并加渐变组。复用 antd 色标交互，由编辑器维护渐变类型、角度和圆心。关闭弹层恢复原选区，色标拖动实时更新，一次手势只记录一次撤销。
- 在选择态作用于整个文字块，编辑态有选区时作用于选中的连续文字，光标态作用于后续输入。不同范围可以分别使用不同渐变和纯色。多段选区内的换行属于同一应用范围。
- 一次应用的范围使用一个渐变坐标系，按实际显示的文字片段外包边界确定。换行、字号变化或富文本标记拆分只改变布局，在同一范围内保持一次连续渐变。线性 0°、45°、90° 在跨行时仍呈现可区分的方向。径向圆心跟随范围边界移动，按圆形计算。
- 为选区中间重新上色时，被覆盖部分使用新颜色，原范围的文字继续共享原渐变坐标系，外包边界按剩余文字计算。分两次选择同一个预设时，各次应用独立。文字背景填色仍由块级效果绘制，渐变填充、描边和阴影在视觉上各自可辨。

### 4.2 文档与渲染

- 使用结构化颜色。纯色沿用现有 hex。渐变存类型、角度或圆心、色标列表，并用块内范围标识区分同值的独立应用。同一范围跨多个文字节点时共享标识和渐变参数，参数或范围变更随文档保存。Tiptap 的命令和复制粘贴应维护作用范围，粘贴产生新的块内范围标识，避免与目标已有范围相连。
- TS 与 Go 同时校验 `defaultStyle.color` 和 `textStyle.attrs.color`。校验色标数量、颜色、有限数值、位置顺序、合法字段和同一标识的参数一致性。混合颜色的显示按颜色描述比较，范围标识只用于渲染分组。保持现有文档传输入口和资源引用行为。
- 实施前半段先做渲染可行性验证。按实际文字布局建立共享坐标，在选区混色的同时保持前景、描边和后置阴影。保留 Tiptap 的光标、选区、输入和换行能力。辅助绘制层不拦截文字编辑。可选实现由原型对照决定。现有独立 `span` 的 CSS `slice` 用于对照，选择最终方案以验收样例为准。
- 同一语义覆盖编辑态 Tiptap、非编辑态、作品缩略图和独立导出渲染入口。导出 renderer 保持现有依赖边界。渐变计算跟随文档和字形布局坐标，预览缩放只改变显示比例。

### 4.3 兼容与验收

保留纯色文档原样读取、往返保存和导出。推荐先更新用户站、管理站、服务端和 worker 的读取与渲染能力，再开放写入。写入后使用支持新文档的版本作为回退目标。发布前检查缓存旧页面的写入行为、既有和排队导出任务、已有模板与本地草稿。实施计划以 v1 继续保存纯色旧文档、新增 v2 表达渐变能力为起点，并用兼容测试验证版本保护和分阶段启用。

**渲染基准**：同一段含纯色和两个独立渐变选区，其中一个选区跨行并局部改字号、字体或字重。分别比较 0°、45°、90° 和径向移动圆心的颜色位置。改样式或换行后渐变仍连续，实色仍可见，阴影在轮廓之外可辨，描边颜色保留，透明 PNG 在字形之外不泄漏渐变矩形。再验证保存重开、撤销、复制粘贴、跨段选择及同一编辑器中纯色↔渐变切换。字号或版面变化后允许渐变随范围尺寸重新计算。

## 5. 卡片高亮

以 `/projects` 作品的 antd 默认悬停反馈为基准。覆盖用户站作品、回收站作品、模板、背景和文案选择，以及后台模板、背景、字体和文案。登录、统计及加载骨架保留静态面板交互。

- 单入口整卡用 antd 默认 `Card hoverable` 或匹配的按钮式卡片反馈。
- 多入口卡片使用相当的阴影和边框反馈，键盘进入任一动作时整卡有反馈，实际焦点仍标在具体动作上。回收站卡片和模板管理卡延续独立操作入口。
- 背景卡的已选中状态持续可见，与即时悬停状态可区分。使用已有主题和减少动态效果配置。

**验收**：鼠标经过和键盘进入时反馈可见，触屏可识别已选中项，卡片菜单、选用和放大仍可分别操作。

## 6. 背景图放大

- **本批已确认范围**：用户站按背景创建和替换两处入口，均使用共享的 `BackgroundPicker`。后台背景资源列表和两站的合成海报模板预览留待后续。
- 卡片提供单独的「放大预览」入口，使用 Ant Design `Image` 受控预览覆盖视口，保留缩放和关闭。列表请求 `previewUrl`，打开大图后再请求同一资源版本的 `asset.url`。预览失败时提供可关闭的失败反馈。
- 保留创建模式的选中与确认、替换模式的单击「选用」。点放大不写入选择、不触发创建或替换。大图关闭后回到原入口并保留筛选、滚动和选中状态。Escape 先关大图，后关背景库。

**验收**：用户站两种模式均可从键盘及手机打开大图并缩放。原图按需请求，失败可关闭，选用交互和当前状态保持。独立导出入口继续遵守 antd 依赖边界。

## 7. 回收站卡片

在 `/projects` 回收站状态下，标题、尺寸和时间占内容区整行，「恢复」「彻底删除」另占底部操作行。可用宽度不足时两个动作改为上下排列，标题过长可省略，按钮保留完整文字、危险样式和触摸命中区。继续沿用原确认流程和删除行为。

**验收**：在 320、360、390px 视口和桌面多列最窄卡片上检查每个按钮的实际边界、页面横向滚动、键盘和确认行为。加入长标题用例并与非回收站作品网格对照。

## 8. 交付顺序和验证

1. 九宫格、卡片高亮、背景预览和回收站卡片可作为前端增量交付。三项卡片相关功能共同回归入口、键盘与五档视口。
2. 阴影与描边先完成纯色场景，再跟随渐变回归。连续字重按 UI、Go 检查和真实导出整条链交付。
3. 渐变先通过渲染基准，再确定布局实现、数据契约及发布门槛。验证文字背景、粗细字重、阴影和描边的组合。如果原型未达到渲染基准，记录差距并保持渐变写入未启用，其他批次可以独立交付。

按仓库约定做定向单测、真实浏览器和导出验收。五档视口为 1440×1000、1024×768、768×1024、390×844 和 320×700。导出证据独立记录尺寸、透明区域和关键颜色采样。像素等价用 ImageMagick 或独立像素断言。所有涉及 MySQL 的验收使用受保护的临时测试库。
