# FastPoster 图文海报项目设计

日期：2026-10-30。状态：整体设计已获用户认可；已按用户补充的本机环境约束修订存储与部署；不是实施计划。

## 1. 项目目标与决策来源

用户需要一个适配桌面和手机的图文海报工具：导入网络下载或 AI 生成的图片，添加多个可编辑文字块，调整位置和文字样式，保持背景图原始像素尺寸导出高质量图片。账号与云端保存让用户可以换设备继续编辑。另有管理后台，维护用户、作品信息、公共素材、模板、级联文案和字体。

用户明确指定：React monorepo；Go 服务端；Hertz、Kitex；接口通过 Thrift IDL 定义。

用户明确确认：移动端采用底部设置面板 A；屏幕缩放只影响预览；拖拽文本框改变宽度、自动换行，字号不随拖拽改变；同块文字可局部设置字体、字号、颜色；支持登录、云端保存和跨设备编辑；后台按本文件列出的完整范围开展。

以下最初属于设计者建议默认值，已随整体设计得到认可：首版画布保持背景原尺寸；具体样式清单、账号方式、文件支持边界、模板格式、后台权限边界与技术库。它们不是用户逐项指定的要求。

用户补充约束：目前无法接入外部对象存储，本机已安装 MySQL 和 Redis。因此首版改为 MySQL + 本机文件系统，Redis 可用于限流；不依赖 PostgreSQL、S3、MinIO、云厂商账号或 Docker。文件存储保留接口边界以便将来迁移，但首版不实现外部对象存储适配器。已有 MySQL/Redis 的实际服务端版本、地址和授权需要在运行环境检查时验证，不从客户端版本推断。

成功标准：手机能顺畅完成导入、输入、排版、保存和下载；局部富文本样式可恢复；导出不使用屏幕预览图片，不随设备缩放丢失分辨率；后台发布的资源能被普通用户实际使用。

| 模块 | 首版交付 |

用户最初将模板等描述为未来扩展，随后同意按完整后台范围开展；本稿建议首版完成相应的最小用户使用闭环，避免出现资源只能管理却不能使用的情况。这是范围解释，用户可在审批时调整。

首版不包含：自定义画布比例、背景裁剪、拼图、多背景图层、图形贴纸、旋转/变形、AI 图片生成、联网搜图或 URL 抓取、多人实时协同、付费、公开作品社区、原生 App、小程序、PSD 等第三方模板导入、JPEG 导出、打印色彩管理。图片来源于网络或 AI 不意味着本项目内置生成能力。

## 3. 核心使用流程与交互

### 3.1 账户和作品

建议首版使用用户名和密码注册登录；无需短信、邮件或第三方账号服务。密码安全散列，服务端保存可撤销会话，以 HttpOnly Cookie 传递；生产使用 HTTPS 和 Secure Cookie。账号恢复由管理员执行一次性重置并要求用户修改密码。管理员账号通过部署时的命令创建，无默认公开密码；普通注册只获得 user 角色。

登录后进入“我的作品”，可从本地图片、公共背景或模板创建作品。首版要求登录后编辑，暂不做游客作品合并。作品属于创建者，默认私有。

编辑停止约 1 秒后自动保存，拖拽期间仅本地更新，结束后保存。界面明确显示保存中、已保存、待重试；图片尚未上传完毕不能标记为已保存。IndexedDB 暂存未同步的编辑快照和必要文件，刷新可恢复；它用于失败恢复，不承诺完整离线功能。主动退出时清理本账号本地草稿。

每次保存带服务端 revision；旧版本保存返回冲突，不能静默覆盖。发生多设备冲突时保留本地内容，提供“加载云端版本”与“将本地另存为作品”。首版不做自动合并。撤销/重做只覆盖当前会话，历史操作栈不要求跨设备同步。

### 3.2 背景与画布

导入后读取服务端校验过的图片尺寸，画布等于应用 EXIF 方向后的图片宽高，不因屏幕尺寸、DPR 或预览缩放改变。背景完整显示、不裁剪、不拉伸。透明图片保留透明；棋盘格只用于编辑辅助，不进入导出。

一个作品只有一张背景。已有作品可以换背景：同尺寸直接替换；不同尺寸更新画布，文字 x/y/宽度按新旧画布对应轴的比例换算，字号、行高和字距不缩放，然后重新换行并限制在画布可编辑范围内。执行前提示尺寸改变和文字可能重新排版，可撤销。第一版不提供独立改变画布尺寸的入口。

预览可用服务端派生的缩略图降低手机解码压力；逻辑画布和文字布局始终使用原始像素坐标，外层统一 transform 缩放。导出永远读取完整分辨率的标准化背景，不读取缩略图。导出不是截图整个编辑页面。

### 3.3 文字块

块属性：id、x、y、width、zIndex、默认文本样式、段落排版、背景/边框/阴影/透明度。高度根据排版自动计算，不是固定裁剪框。

块操作状态为未选中、选中、编辑文字。单击/点按选中，拖块体移动；已选中块再次点按文字或点击“编辑文字”进入输入。编辑状态不允许拖动块体；点击空白或“完成”退出。辅助工具栏提供复制、删除、前移/后移、编辑，避免依赖长按菜单。

调宽使用左右两侧把手，不放暗示等比缩放的角点。拖动把手保持另一侧锚点，width 以原图像素变化，自动换行，字号不变；高度自然变化。文字允许中文、英文、数字、标点、多段落和手动换行。连续长字符串也可换行。

局部样式：字体、字号、颜色、粗体/字重、斜体、下划线、删除线。块/段落样式：左中右对齐、相对行高、字距；整块描边、阴影、背景色、内边距和透明度。行高默认 1.4 倍、字距默认 0，具体面板取值范围由实现者合理设置。旋转、竖排、渐变文字和弯曲文字后续考虑。

有文字选区时，字体/字号/颜色等只作用于选区；光标无选区时改变后续输入样式；选中块但不在编辑状态时作用于整块并替换对应局部属性。选区样式不一致时面板显示“混合”。底部面板操作保留富文本选区，IME 组合输入期间不重建编辑器、不打断输入。

文本块 top-left、宽度及排版区域保持在画布内；输入或调宽导致高度超出画布时显示溢出提示，保留内容但阻止正式导出，用户通过调宽、字号或位置解决。阴影与描边越过画布边界的部分按画布边界裁切。删除和修改可撤销，不静默截断正文。

### 3.4 手机操作

采用已选 A：选中文字块后，在画布下方展开可收起的面板，以文字/字体/样式/排版分组。输入时兼容软键盘和动态视口，保留当前文字可见区域；退出输入后恢复画布视野。面板不覆盖顶部导出/保存状态。

单指操作选中文字块；空白区单指平移；双指缩放平移视图，均不修改作品坐标。文字编辑时保留系统选词和光标操作，不抢占输入区域的原生手势。把手触摸热区至少 44 CSS px，显示上可更小。所有关键动作都能用明确按钮完成，桌面端提供键盘删除与撤销等快捷键。

目标是响应式 Web：桌面 Chrome/Edge、Android Chrome、iOS Safari 最近两个主要版本，最低布局宽度 360 CSS px；这是一组待验证的验收目标，不是现成兼容性承诺。

## 4. 图片支持与“无损”的明确含义

以下为建议首版支持边界，避免“任何格式、任意尺寸”成为无法验证的承诺。

| 项目 | 建议默认值 |
| --- | --- |
| 背景导入 | 静态 JPEG/JPG、PNG、WebP，扩展名和真实内容均校验 |
| 单文件上限 | 40 MiB |
| 解码尺寸 | 总像素不超过 40,000,000，任一边不超过 8192 像素；双重约束 |
| 色彩 | 常见 8 位图片，标准化至 sRGB RGBA8；保留 alpha；应用 EXIF 方向 |
| 不支持的输入 | 动图（包括动画 WebP/APNG）、SVG、HEIC、AVIF、TIFF、PSD、16 位/HDR/CMYK；明确提示，不静默取帧或降低精度 |
| 输出 | 原画布 W×H 的 RGBA PNG，无水印，无额外缩放，无 JPEG 重压缩 |
| 预览派生图 | 最长边建议 2048 像素，按需生成缩略图；不作为导出源 |

原始上传文件按原字节保存。标准化背景是另一个对象：处理方向与色彩但不缩小像素尺寸，采用 PNG 保存；限制和错误在应用为背景前展示。原始文件和标准化文件分别统计存储，避免将缩略图误认为原图。

“无损”指最终 RGBA 像素采用 PNG 无损编码，并在合成前不降分辨率。它不代表输出与原文件字节相同、不代表恢复 JPEG 已有损失，也不承诺保存原始 ICC、EXIF、宽色域、16 位和 HDR 工作流。8 位宽色域输入转 sRGB 可能发生色域变化，导入信息中明确展示标准化结果；如要求归档级像素/色彩保真，应另行扩大范围。

### 4.1 渲染与导出方案

设计者建议 React DOM + Tiptap 富文本，以共享文档模型、样式规则和静态 DOM 渲染组件统一编辑与导出。选择它是因为局部多字体/多字号输入是核心需求；不在 Canvas 中另写一套文本编辑和换行算法。

正式导出由 Go 异步 worker 驱动锁定版本的 headless Chromium（建议 chromedp）。服务端使用同一 React 静态渲染模块，加载作品保存时锁定的字体资源，按 1 逻辑 px = 1 输出像素布局。等待字体与资源完成、排版稳定后，生成透明文字图层 PNG；Go 将该图层按 alpha 合成到完整分辨率的标准化背景，再编码最终 PNG。这样未覆盖区域可以与标准化背景做像素一致性检查，也避免 Chromium 再处理背景带来的额外差异。

渲染页面只在 worker 内部可访问，接受经过校验的结构化快照，不接受用户提供 HTML、CSS、脚本或任意远程资源。截图范围是画布本身，DPR 固定 1，隐藏所有辅助边框与选区。渲染器使用透明背景，实际输出尺寸必须在保存对象前再次解码验证。

浏览器即时预览使用相同布局规则，缩放插值和不同平台抗锯齿可能有像素差异；不承诺所有浏览器逐像素相同。导出前提供服务端生成的最终结果预览，用户下载的就是该结果。缺失字体、排版溢出或资源未就绪必须报错，不能用默认字体悄悄替换。

实现前段需要做渲染可行性验证：混合字号/字体的中文换行、手机输入、透明图层合成、4000×6000 输出以及上限横/竖长图。40MP/8192 是容量目标，必须在固定部署资源上验证后才能作为产品承诺；若不能达标，优先限制并发或提高 worker 资源，不能静默缩图。

### 4.2 导出任务

导出先保存待导出的不可变版本；未完成上传/未保存/冲突未解决的文档不启动任务。用 revision、内容散列、字体与渲染器版本锁定输入。编辑期间继续修改不会改变已创建的任务。

任务状态：queued → running → succeeded/failed。首版轮询状态，无需 WebSocket。成功提供缩略预览与原尺寸下载；失败展示原因，可重新提交。使用幂等 key 防重复点击；固定输入可复用未过期结果。每用户最多 1 个运行中任务、2 个排队任务；默认单 worker 并发 1、单任务 120 秒，租约 30 秒并续期，失效任务可重领，最多 2 次自动尝试。这些均为可配置运行默认值。

MySQL（InnoDB）保存任务、快照和执行租约，worker 通过事务领取任务，重启可恢复。需要支持 JSON、事务及 SELECT ... FOR UPDATE SKIP LOCKED 的 MySQL 8.0+ 兼容服务；目标兼容 MySQL 8.4 LTS，实施时通过实际服务检查。Redis 不作为导出任务、作品或文件的唯一存储；不额外引入消息队列。临时文件任务结束后清理。成功结果保留 7 天，可从作品再导出；到期仅删结果，不删作品。下载经 Hertz 鉴权并限制为任务所有者，不提供本机目录的公开静态映射。

## 5. 模板、背景、文案和字体

### 5.1 公共背景

后台上传并完成图片校验/标准化后才可发布。维护名称、分类、排序、缩略图和上下架状态。用户选用时记录不可变资源版本引用；管理员下架仅影响新选择，已有作品仍可读取其引用版本。已有引用的文件不能直接物理删除。

### 5.2 模板

模板是带固定背景、画布原尺寸和富文本块的作品快照。应用模板创建新的用户作品，不修改原模板，不自动适配到别的背景比例。

建议首版定义 FastPoster ZIP 模板包：manifest.json、版本化的海报文档、所需背景文件和字体依赖清单（不嵌入字体文件）。模板包不包含脚本、HTML、外部 URL 或用户账号信息。管理员从已有模板/后台内嵌编辑器创建、导入、预览、导出、发布或下架；用户可在模板选择处导入模板包成为自己的私有作品，并可导出作品为模板包。

依赖字体必须在系统字体库中存在；缺失时明确列出并阻止应用，不静默替换。ZIP 导入限制为 80 MiB 压缩体、120 MiB 解压体、最多 20 个文件，拒绝路径穿越、嵌套压缩、非约定文件和非法 asset 引用；背景仍遵循图片上限。首版模板不包含动态变量、多人共享编辑或批量数据生成。

### 5.3 级联文案

“级联”按分类树理解，例如主题 → 场景 → 风格 → 文案；最多 5 层，可配置名称和顺序，禁止循环。后台维护分类树、文案标题/正文/排序/上下架和关键字。用户选到分类后查看文案；无选中文字时插入新文字块，有文字选区时替换选区并继承当前样式。文案本身默认纯文本，不绑定模板字段、不包含预算计算逻辑。用户最初的“预算文案”在本稿中解释为“预设文案”，这是设计者判断。

### 5.4 字体

首版随部署内置一套可再分发的中文字体及至少正常/粗体两档，避免依赖用户系统字体。管理员管理字体名称、家族、字重、正常/斜体样式、文件、预览、排序、上下架及授权说明。上传初期支持 WOFF2、TTF、OTF，经解析验证后存储；字体样式只展示实际存在的字重，缺失的粗体/斜体不进行人工合成。

字体文件发布为不可变版本，文档引用 fontAssetId 和版本，不保存用户任意 font-family 名称。普通用户不自行上传字体。字体下架不影响已有作品，禁止物理删除仍被作品或模板引用的版本。首版支持中文常用字、拉丁文、数字标点；缺字明确提示；彩色 emoji 和复杂多语种排版不作为精确保真验收对象。

## 6. 管理后台与权限

独立 admin 应用，与 web 共用组件、API 客户端和海报编辑核心。角色首版为 user/admin 两种，不搭建可配置权限平台；所有管理接口在服务端验角色，隐藏按钮不构成权限控制。

| 页面 | 核心操作与边界 |
| --- | --- |
| 概览 | 用户数、作品数、原始/标准化/导出存储用量、导出成功/失败计数 |
| 用户 | 列表搜索、详情、禁用/恢复、密码重置；禁用撤销会话，保留作品 |
| 作品信息 | 按用户/时间筛选元信息、尺寸、更新时间、占用空间和导出任务；默认不查看或编辑用户私有图片与文字正文 |
| 公共背景 | 上传、分类、排序、预览、发布/下架 |
| 模板 | 管理公共模板、模板包导入/导出、调用共享编辑器修改草稿、预览、发布/下架 |
| 文案 | 分类树、文案列表、搜索、编辑、排序和上下架 |
| 字体 | 字体/字重文件校验、预览、发布/下架、引用关系 |
| 导出任务 | 状态、耗时、错误类别、任务编号；不公开私有下载地址和作品正文 |
| 操作记录 | 管理员、时间、对象、动作、结果；不记录密码或私有文案内容 |

首版没有管理员代改用户作品或一键清空用户数据的功能。普通用户只访问自己的作品/上传资源/导出结果，以及已发布公共素材。作品删除为软删除，资源回收由延迟清理处理引用关系；首版建议 30 天恢复窗口，期间用户可恢复作品。存储用量是技术统计，不引入计费。

## 7. 系统架构与职责

```text
apps/web ───┐
            ├─ HTTP JSON / upload / session ─→ Go Hertz gateway
apps/admin ─┘                                  │
                                               │ Kitex RPC / Thrift
                                               ▼
                                       Go core 业务服务
                                         │           │
                                      MySQL     本机文件目录
                                         ▲           ▲
                                         │           │
                                  Go export-worker ──┘
                                         │
                          内部 Chromium + apps/renderer
                               共享 packages/poster-renderer
```

建议同仓库、单 Go module、多个可执行程序：gateway 对外提供 HTTP；core 以一个 Kitex 服务承载账号、作品、素材和管理领域；worker 独立运行以隔离 Chromium 的资源消耗。先做模块边界，不为每一张表拆独立微服务。浏览器不直接调用 Kitex；未引入 Node 业务服务，renderer 是打包的前端静态渲染页面，由 Go worker 内部提供。

Hertz 处理路由、请求绑定、会话提取、上传流和 HTTP 错误；core 执行授权、校验、事务和领域逻辑。gateway 向 core 传递从会话验证得出的身份上下文，不能信任客户端自填 userId/admin；core 对资源归属再校验。内部 RPC 不对公网暴露，部署网络限制调用来源。

MySQL 保存结构化信息、JSON 作品文档、版本快照、可撤销会话和持久化任务；统一 InnoDB、utf8mb4 和 UTC 时间。保存文档通过带 expectedRevision 的条件更新处理冲突，不能依赖 PostgreSQL JSONB、RETURNING 或特定数据库锁语法。

本机文件系统保存原始上传、标准化背景、缩略图、字体、模板附件和导出 PNG。APP_DATA_DIR 指定持久化根目录，本地默认 `./var/data`；运行数据加入 Git 忽略。建议目录按 originals/normalized/previews/fonts/templates/exports/tmp 分区，文件名使用服务端生成的不透明键，数据库仅存相对键、尺寸、散列、大小及引用关系，不保存前端可控制的绝对路径。

统一 FileStore 接口承担流式写入、读取、元信息和删除。gateway/core/worker 原生运行在同一台机器，共享同一个 APP_DATA_DIR 的绝对路径；二进制不塞入 Thrift 大字段。上传先写根目录内临时文件，校验成功后在同一文件系统内原子重命名，再登记数据库可用状态；数据库登记失败产生的孤立文件由清理任务回收。文件和数据库不假装处于同一个原子事务中。缺失文件和磁盘不足返回明确错误，不能标记保存或导出成功。

私有素材与导出通过鉴权 HTTP 流式读取，支持合理的 Content-Type/Content-Disposition，不将 APP_DATA_DIR 直接暴露为静态资源目录。渲染器仅通过内部受控读取端点访问本任务锁定的文件；用户不能借 assetId 或路径读任意文件。FileStore 使用根目录约束并拒绝路径穿越、符号链接逃逸；客户端 URL 不包含绝对文件路径。

Redis 首版仅可选用于登录限流等短期状态，不保存文件或权威作品数据。未配置 Redis 时可用单机内存限流；Redis 故障有有界内存降级，不影响已有会话与持久化任务恢复。为后续外部对象存储迁移保留相对键和 FileStore 边界，暂不开发 S3/OSS SDK、预签名上传或相关设置页面。

默认原生本机开发部署：复用已有 MySQL 和 Redis，运行 Go gateway/core/worker 与 Vite 开发服务；不要求安装 Docker、MinIO 或新数据库服务。提供环境变量示例、数据库迁移、检查命令与一键启动/退出脚本，不写入实际数据库密码。gateway/core/worker 统一解析同一个 APP_DATA_DIR，启动时检查目录可读写与剩余磁盘空间。备份说明覆盖 MySQL 和文件目录的一致备份/恢复，单独备份数据库不能恢复背景图。

静态前端可由 gateway/反向代理提供，生产同源路径 /、/admin、/api；开发用 Vite proxy。首版服务寻址使用配置固定地址。导出仍需要 Chrome/Chromium，图片标准化仍需要转换工具；两者是程序运行依赖而非额外存储服务，不能因换为本机文件而删除对应校验。部署脚本检测依赖并给出安装方式，不自动安装系统服务。容器化和多机存储部署留到后续。

## 9. 文档模型、IDL 和接口边界

### 9.1 作品文档

海报文档使用版本化 JSON，不把 HTML 当持久化格式。结构包括 schemaVersion、canvas(width,height)、background(assetId,version)、textBlocks 和字体版本引用。块内富文本用受限段落/文本/硬换行节点及 marks 表达，不支持任意嵌套 HTML、图片、链接或脚本。

x/y/width/fontSize/letterSpacing 单位是原图像素，可用有界小数；行高为倍数。块高为派生结果，布局检查记录所用渲染版本。字号精度、坐标范围和内容长度由 schema 在客户端及 Go 端同时校验；建议最多 100 个文字块、单块 10,000 字符、文档 2 MiB。旧文档只通过显式迁移升级，不在读取时猜测字段。

### 9.2 Thrift 是服务契约的唯一来源

HTTP 与 RPC 服务分别定义在 Thrift，include 公共业务 DTO。HTTP IDL 带 Hertz api.* 注解，生成路由/绑定模型；RPC IDL 生成 Kitex 服务端与客户端。二者通过明确适配层转换，不耦合两套生成器的输出目录。

前端走 HTTP JSON，使用从同一 Thrift AST 派生的 TypeScript DTO、路由方法元数据和客户端绑定；首版生成脚本可仅覆盖项目实际使用的 Thrift 子集，遇到不支持的类型要失败。计划阶段确定生成器实现，CI 重新生成并检查无差异。不得手写一套长期独立的前端业务 DTO。HTTP JSON 中所有 i64 标识与 revision 采用十进制字符串，明确处理 JS 精度。

文档 JSON 在 API/RPC 中以有 schemaVersion 的结构化载荷传输，Thrift 定义信封，poster-schema 管具体文档约束；传 string JSON 时 Go 必须解析并验证，不允许不透明透传。公共错误包含 code、message、requestId、可选字段错误；HTTP 认证/权限/冲突/超限/校验错误分别映射合适状态码，前端不解析异常文本判断业务分支。

接口域：Auth（注册、登录、退出、当前用户）、Projects（列表、读取、创建、带 revision 保存、复制、删除、恢复）、Assets（上传完成、元信息、受权读取）、Catalog（背景/模板/字体/文案）、Templates（导入/导出包）、Exports（创建、状态、结果下载）、Admin（用户、资源、操作记录、任务概览）。所有列表具有分页与最大页大小。

### 9.3 持久化实体

建议实体：users、sessions、projects、project_revisions、assets、asset_versions、project_asset_refs、font_families/font_faces、background_categories/backgrounds、templates/template_versions、copy_categories/copy_entries、export_jobs、admin_audit_logs。

作品存当前 MySQL JSON 文档与 revision；导出和模板发布保存不可变快照，不要求保存每个输入字符的永久历史。所有资源版本不可变，引用表维护活跃作品/模板/任务的依赖。软删除、过期结果和孤立上传在确认无引用后回收，不能通过后台下架破坏已有作品。

## 10. 可靠性与实现边界

用户上传文件在应用前检查真实格式、动画标志、颜色/位深、宽高和解码预算，转换使用可控内存和超时的进程；建议用版本已记录的 ImageMagick 处理 EXIF/ICC 转换，限制 coder 为允许的格式并禁用外部 delegate。具体调用方式和本机安装版本由实现者确认，不能通过拼接文件名构造 shell 命令。

上传失败不创建可用素材；暂存文件用有期限状态清理。模板或作品引用素材须属于当前用户或可用公共版本。字体加载失败和缺字有可追溯错误。导出故障不影响已保存作品；worker 重启可继续领取任务。管理员下架不使旧作品丢字体/丢背景。

首版维护用户/admin 角色、会话撤销、资源归属、CSRF 同源检查和管理审计；不扩展到企业 SSO 或权限平台。密码、原始文案、会话和私有下载凭据不写日志。结构化日志贯穿 HTTP/RPC/导出 requestId 和 jobId；记录队列长度、耗时、错误原因与存储占用，便于判断容量。

## 11. 验收与需要先验证的风险

1. 使用至少横图、竖图、方图、透明图创建海报；导出 PNG 宽高精确等于标准化背景宽高；预览缩放、浏览器 DPR、窗口大小不影响结果。
2. JPEG/PNG/WebP 均完成导入、保存、跨设备重开与导出；损坏、超限、伪扩展名、动图、16 位等返回明确错误；EXIF 方向和 ICC 转换有固定样例。
3. 同一文本块混合中文/英文和多字体/多字号/多颜色，调宽保持字体样式不变、换行正确、没有截字；重复保存/读取不丢 marks。
4. 固定 Chromium/字体/渲染版本下重复导出结果像素稳定；透明叠层合成后，远离文字及其阴影/描边的背景像素与标准化背景一致；PNG 解码后 alpha 符合预期。
5. 画布在真实 Android Chrome 和 iOS Safari 的 360px 宽视口上完成 IME 输入、局部选词、底部面板修改、拖拽、调宽、双指缩放与下载；手机最终下载与桌面同一导出任务的文件散列一致。
6. 4000×6000 和接近双重上限的横/竖图片，在约定 worker 资源下无缩小导出；测量峰值内存、耗时、失败恢复和并发限制，明确容量达标后再对外宣称上限。
7. 自动保存遇到断网、刷新和多设备冲突不静默覆盖内容；云端已保存作品可在另一设备恢复。
8. 普通用户不能访问他人作品、素材或导出；不能通过修改请求获得管理员角色；禁用后会话失效。
9. 后台发布背景、模板、文案和字体后，用户能完成实际使用；下架后已有作品仍可打开和导出；缺字体的模板包被明确拒绝。
10. Thrift 一次修改能重新生成 Hertz/Kitex/前端契约；契约漂移检查、Go/前端构建、关键 API 集成与渲染回归通过。
11. 在没有 PostgreSQL、对象存储和 Docker 的本机，仅使用配置的 MySQL、可选 Redis 与持久化文件目录，完成上传、重启后恢复、导出下载和备份恢复；磁盘不足、文件缺失、路径逃逸、写文件成功但数据库提交失败均不能造成越权或虚报成功。

验证顺序建议：先验证富文本输入和排版/导出路线，再进入完整应用实施。当前仅设计，不声称这些检查已经通过。

## 12. 留给实施者的选择

允许实施者决定具体 CSS 细节、组件拆分、SQL 查询库、表索引、日志库、测试工具和生成脚本组织；可以优化后台表格与筛选交互，但不能改变原图尺寸语义、富文本能力、授权范围或删减已批准首版模块。

需要在实施计划中固定工具链版本、生成命令、容器资源与渲染风险验证步骤。遇到容量实测不达标或新格式需求时，不能以预览图导出或静默转换绕过要求，应回到产品范围讨论。

## 13. 核查依据

- [CloudWeGo Hertz/Kitex 定位](https://www.cloudwego.io/docs/)：Hertz 为 HTTP 框架，Kitex 为 RPC 框架；采用 gateway → RPC core 的职责划分是本设计选择。
- [Hertz hz 注解](https://www.cloudwego.io/docs/hertz/tutorials/toolkit/annotation/) 与 [Kitex 生成流程](https://www.cloudwego.io/docs/kitex/getting-started/tutorial/)：核实 Thrift 驱动 HTTP 路由绑定与 RPC 代码生成的基础能力。前端 TS 生成不属于这些文档承诺的默认产物。
- [Tiptap TextStyleKit](https://tiptap.dev/docs/editor/extensions/functionality/text-style-kit)：包含字体、字号、颜色等局部样式基础；本项目仍需补充文档限制、块排版与双端渲染一致性。
- [chromedp 项目](https://github.com/chromedp/chromedp) 与 [Chromium Page.captureScreenshot](https://chromedevtools.github.io/devtools-protocol/tot/Page/#method-captureScreenshot)：核实 Go 驱动浏览器及 PNG 捕获能力，不作为 40MP 性能或多浏览器像素一致性的证明。
- [W3C PNG 规范](https://www.w3.org/TR/png/)：PNG 支持无损像素编码与 alpha；本项目的 sRGB/位深边界另由本设计限定。
- [MySQL InnoDB 锁定读](https://dev.mysql.com/doc/refman/8.4/en/innodb-locking-reads.html)：SKIP LOCKED 可用于队列式表的并发领取；任务完成仍需租约与执行者标识校验，不能只靠领取时的行锁。
