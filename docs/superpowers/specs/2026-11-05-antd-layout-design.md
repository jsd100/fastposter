## UI-01 范围、依据与数据归属

迁移覆盖用户站、管理站及两站共用的编辑器界面。两站的通用控件和页面布局采用 antd。图层、画布、富文本、字体预检、撤销和本地草稿由已有领域代码提供，必要时用 antd 控件组合成适配器。Go 服务、持久化、生成契约、海报文档和导出运行时是本次 UI 的既有接口。页面继续通过现有路由与客户端请求这些接口。

| 区域                     | 实际来源                                                       | 责任                                       |
| ------------------------ | -------------------------------------------------------------- | ------------------------------------------ |
| 两站导航、主题和通用交互 | `apps/web`、`apps/admin`、`packages/ui`                        | 路由、组件、弹层、通知、布局、可访问性     |
| 文档、选区与操作历史     | `packages/poster-editor`、`packages/poster-schema`             | 同一编辑会话、有效数值、字体引用、撤销事务 |
| 本地草稿和导出任务       | `apps/web/src/features/editor`、`apps/web/src/features/export` | 用户和作品归属、版本、提交与恢复           |
| 渲染和 PNG               | `packages/poster-renderer`、`apps/renderer`、现有导出 worker   | 自然尺寸、字体资产、最终像素               |
| 身份、授权和业务数据     | `packages/api-client`、`idl`、现有 Go/MySQL 服务               | Cookie、服务端校验、资源归属、分页和状态   |

最新用户指示决定工作范围和是否开工，仓库 `AGENTS.md` 约束执行。本规范定义页面行为和验收，计划定义步骤和接口。原型表达视觉设计，源代码及现有行为测试确定业务契约。如果原型的样例按钮、模拟任务或示例内容与现有应用不一致，保留真实应用行为，按本规范指定的布局呈现。涉及新增权限、路由、接口、数据库迁移、保存策略或文档格式的决定，由用户单独确认并更新两份文档。

## UI-02 视觉体系和控件规则

海报预览承担主要色彩和视觉表现。作品集使用浅灰背景。编辑区用中性画布外围，面板保持白底。界面中文优先使用系统中文无衬线字族。实际海报文字由其文档中的字体资产决定。

| 角色       | 取值      | 使用位置                 |
| ---------- | --------- | ------------------------ |
| 内容表面   | `#FFFFFF` | 面板、表单和菜单         |
| 工作区底色 | `#F3F5F4` | 作品集和后台底色         |
| 画布外围   | `#E6EAE7` | 编辑画布和图库衬底       |
| 主要文字   | `#202C25` | 正文、标题和当前值       |
| 主操作色   | `#2E694F` | 新建、导出和当前页签     |
| 危险色     | `#A63232` | 失败与不可恢复操作       |
| 辅助正文   | `#526159` | 时间、尺寸说明和次要信息 |

标签 13px，正文和常规控件 14px，辅助信息 12px，页面标题 24–29px。间距以 4、8、12、16、24px 为基础。普通控件高 36px，属性区紧凑操作 32px，手机触摸目标至少 44px。表格数字用等宽数字对齐。画布和缩略图居中，界面文字左对齐。键盘焦点清晰可见。选中、危险、加载、失败状态由文字或可访问名称与颜色共同表达。图标操作保留可访问名称，长作品名在窄屏允许截断但仍可识别。动效尊重 `prefers-reduced-motion`。

两站用共享 `ConfigProvider` 和 antd `App` 提供中文 locale 与主题。编辑器可以在局部使用紧凑密度。可复用样式使用语义 token，页面几何使用局部布局类，控件优先使用公开 `classNames` / `styles`。主题及 reset 的作用域是两站界面。海报缩略图、编辑画布和 renderer 的文档文字测量继续采用海报本身的样式。 [antd 主题](https://ant.design/docs/react/customize-theme/)

## UI-03 路由与登录

| 入口                                                                    | 现有职责                 | 迁移验收                                             |
| ----------------------------------------------------------------------- | ------------------------ | ---------------------------------------------------- |
| `/login`、`/register`                                                   | 用户登录、注册           | 当前字段、提交和提示可用，未认证访问作品仍回登录     |
| `/password`                                                             | 已登录修改密码、强制改密 | 必须改密的用户按原顺序访问，成功按原规则更新会话     |
| `/password?reset=1`                                                     | 通过重置令牌重设密码     | 直接打开此 URL 进入重置表单                          |
| `/projects`                                                             | 我的作品、回收站、模板库 | 顶部导航，同一路由内切换列表                         |
| `/projects/:id/edit`                                                    | 用户编辑工作台           | 以当前账号与作品 ID 关联数据与草稿                   |
| `/admin/login`、`/admin`、`/admin/`                                     | 后台认证入口及重定向     | 匿名回后台登录，管理员进入概览，普通账号看到权限提示 |
| `/admin/overview`、`/admin/users`、`/admin/projects`                    | 概览、用户、作品元数据   | 保持管理员权限和现有操作                             |
| `/admin/backgrounds`、`/admin/templates`、`/admin/fonts`、`/admin/copy` | 内容资源                 | 保持列表、筛选、上传与管理动作                       |
| `/admin/jobs`、`/admin/audit`                                           | 导出任务、审计           | 保持原数据范围、分页和轮询                           |

登录、注册和密码页沿用现有信息结构，应用统一表单和主题。默认按钮类型是 `button`，显式提交使用 HTML `submit`，封装内部映射到 antd 的 `htmlType`。保持字段关联、`required`、`autocomplete`、错误文本及 busy 防重复提交。真实身份由现有会话与服务端角色决定。退出、会话过期和跨标签换账号继续使旧查询、通知和草稿访问失效。导航保持浏览器前进、后退与修饰键链接行为。

## UI-04 作品集和回收站

顶部依次为品牌、我的作品、回收站和账号入口。标题区保留“模板库”与主要操作“新建海报”。搜索在网格上方，匹配数量靠右。宽度 ≥881px 四列，681–880px 三列，≤680px 两列。陈列位等高，海报按原比例完整显示。标题、尺寸、现有时间信息和条目菜单位于缩略图下方。

| 状态           | 界面和操作                                               | 数据边界                                 |
| -------------- | -------------------------------------------------------- | ---------------------------------------- |
| 正常           | 点击缩略图进入编辑。条目菜单提供重命名、复制和移到回收站 | 使用现有作品 ID、查询和操作              |
| 加载           | 稳定的加载状态                                           | 暂未返回时不显示无结果，也不触发页码回退 |
| 首次或作品为空 | 提供选择背景图、从模板开始                               | 按现有上传或模板应用流程新建             |
| 搜索无结果     | 显示当前查询无匹配及清除入口                             | 查询提交后以服务端数量为准               |
| 请求失败       | 错误与重试入口                                           | 保留当前筛选，重试同一查询               |
| 回收站         | 分开显示可恢复作品和后台清理状态                         | 两组请求及页码独立                       |

作品列表服务端每页 24 条。保留搜索防抖、提交关键字后回到第一页的行为。进入编辑再返回时恢复同一会话的回收站状态、搜索输入、已提交关键字、作品页、清理任务页和滚动位置。用当前用户校验暂存状态。渲染有效结果后恢复滚动。退出、会话过期或换账号进入自己的列表状态。成功响应显示末页已缩减时回到最近有效页。

回收站的软删除与彻底删除使用不同操作。恢复仅针对可恢复作品。彻底删除展示作品标题和 ID、不可恢复说明和共享资源保留规则，默认焦点在“取消”，提交中防止重复确认。管理员确认还需要勾选已核对归属。待清理和 `retry_wait` 使用现有清理状态、轮询和“重试清理”，重试更新匹配任务 ID 的记录。只有任务 `completed` 才反馈已清理完成。即使列表首次轮询未见到已接受任务，也继续按已接受 ID 追踪完成。跨标签彻底删除继续阻止原作品的自动保存与草稿复活。 [既有删除验收](../../verification/2026-11-05-project-permanent-deletion-review.md)

## UI-05 素材选择、上传与模板

- “新建海报”承接现有本地图片文件选择和拖入。保留 40 MiB 的前端检查及现有服务端格式校验。选择文件后使用现有 FormData、Cookie、客户端错误与重试机制。
- 作品集“模板库”继续支持目录筛选、已有模板应用和 ZIP 导入。应用模板新建独立作品，按返回 ID 打开。当前作品使用的资源版本继续由文档引用。
- 编辑器“背景”保留上传与可用背景库入口。取消时不提交修改。替换相同尺寸背景按原行为应用。尺寸不同时先显示目标尺寸与确认提示，确认后使用现有几何变换；文字位置和文本框按比例调整，字号保持原值，可撤销。
- “文案”保留搜索、五级分类、可选父级分类及已有插入/替换行为。可编辑范围由原编辑器决定。应用文案沿用一次撤销。
- 后台背景和字体保留文件上传、字体字重/样式、授权、分类、编辑、发布和下架。模板保留预览、导入、保存和发布。文案保留分类树、搜索、列表与编辑。后台模板全屏打开共享 `Editor`，关闭时回到原分类、搜索和页码，并恢复到可用的触发入口。
- 显示加载、空目录、错误与可重试状态。嵌套选择器遵循 UI-10 的焦点、遮罩与 Escape 规则。所有导入继续使用当前 API 及其文件和权限约束。

| 屏幕宽度   | 默认布局              | 辅助区域                                       |

用户顶栏固定展示返回、作品名、保存状态和导出。常用创作操作集中在第二行。后台模板在工作区顶部展示模板名称、分类、排序及保存/发布所需控件，使用同一套画布和属性布局。返回、保存、取消、关闭工作区等操作按现有业务回调处理。

手机底部顺序为文字、背景、文案、图层。点“文字”打开属性，标题旁始终有“添加文字”。未选中时提供添加入口和选中现有文字的提示。已有选区时也能添加，新建后选中新块并使用原有进入编辑/选择流程。属性面板打开后，让正在调整的文字在面板上方可见，保持实时反馈。窄屏控件可单列，面板自身滚动，处理键盘和底部安全区。关闭面板将焦点还给触发按钮或最近的等价入口。

保留图层复制、删除、前移、后移和选择，保留画布平移、缩放、双指操作、拖拽与调整宽度。画布尺寸以文档像素显示。当前缩放、布局适应、辅助区开关属于视图状态。打开面板、切换属性分组和跨断点不改变文档、不建立撤销项。调整视图可重新适应显示区域，实际文字位置、宽度及字号保持文档定义。

## UI-07 属性分组、选区和事务

| 分组 | 控件                                                      | 写入范围                   |
| ---- | --------------------------------------------------------- | -------------------------- |
| 文字 | 字体、字重、字号、颜色、预设和现有粗体/斜体/下划线/删除线 | 依现有整块、选区或光标模式 |
| 段落 | 对齐、行高、字距                                          | 当前文字块已有段落属性     |
| 效果 | 不透明度、内边距、背景色、描边、阴影与清除                | 当前文字块已有的效果字段   |
| 位置 | 横向 X、纵向 Y、宽度                                      | 当前文字块的文档坐标和宽度 |

在属性区说明操作目标为整块、光标或选区。同一范围的不同数值显示“混合”，不擅自选一个值写回。切换分组、弹层焦点转移、断点变换和移动键盘保持原编辑会话及选区。关闭辅助区不会结束作品编辑会话。若 UI 需要重挂载属性组件，草稿应按会话、文字块和属性恢复。新选中的块使用自己的草稿和值，关闭作品、被删除或切换账号后销毁旧会话的临时状态。

画布几何继续由当前 `Stage`、`geometry.ts` 和 store 处理。点击选择、拖拽和拉伸维持已有区别，锁定背景不变成可编辑文字。宽度调整产生自然换行。字号保持由文字属性决定。操作使用当前文档坐标约束，视觉缩放百分比不作为写入坐标。撤销、重做与 `onInteractionChange` 继续关联现有事务。

## UI-08 数值输入、字体及颜色

数值输入同时保存可编辑字符串和有效文档值。采用已有 `classifyNumberDraft`，包括全角字符规范化和 Unicode 减号。空、负号、尾随小数点是草稿。非法文本或越界文本可纠正，文档仍使用最近有效值。有效值按照已有时机写入，Enter 或用户主动失焦整理显示，Escape 恢复当前输入会话开始时的值。输入法组合期间避免错误提交或画布快捷键。范围、步长、方向键和动态边界由当前调用处给出。

| 例子                                | 预期                                                           |
| ----------------------------------- | -------------------------------------------------------------- |
| 字距当前为 `12`，输入 `0.`          | 输入显示 `0.`，文档仍为 `12`，Escape 恢复 `12`                 |
| 字距允许负数，输入 `-.5`            | 文档为 `-0.5`，失焦后规范显示                                  |
| 字号已为 `4096`，键入 `4097` 后步进 | 仍为 `4096`                                                    |
| 字号值混合，点一次步进              | 用已有 `stepBase` 得出首个有效值，不把混合状态当作 0           |
| 长按步进                            | 只有一次开始和结束，撤销一次恢复按压前数值，取消或卸载结束重复 |
| 字距键入 `12.` 时从桌面转手机       | 恢复原字符串和选区，未完成输入不写文档、不增加历史             |

至少保留已测范围：字号 `1..4096`、行高 `0.5..5`、字距 `-100..1000`。位置、宽度及效果从现有 schema 与动态几何约束取值。透明度界面使用百分比，文档使用 `0..1`。普通数字控件可用 `InputNumber`。编辑器用原始输入与事务测试判断能否用其 spinner，必要时由 antd `Input` 和 `Button` 组合保留完整契约。

字体选择保留分组、搜索、键盘高亮预览、禁用和真实字重。高亮只预览。中文选区中的 Inter 仍禁用。有效选择继续经过资产加载、字形检查和 `useFontChoice` 的快照校验，校验目标包含作品作用域、文档、文字块及选区。迟到的成功或失败只作用于仍匹配的请求，错误与重试属于当前范围。实际导出引用同一字体资产及版本。保留可选择的色板，`ColorPicker` 依现有字段序列化为六位或八位 hex，透明哨兵 `#00000000` 可保持，颜色对象只用于界面。

## UI-09 保存、草稿和导出

现有自动保存控制器负责 `expectedRevision`、1000ms 防抖、并发保存、事务阻塞、恢复和删除。顶栏状态直接由其结果派生。面板开关或选区变化属于界面状态。草稿用 `userId + projectId` 定位。冲突按现有入口加载已保存版本或将本地修改另存，文案使用“已保存版本”。前端错误必须由真实加载、保存和导出状态产生。

| `SaveStatus` | 建议短文案              | 可见行为                     |
| ------------ | ----------------------- | ---------------------------- |
| `saved`      | 已保存                  | 已获服务端确认               |
| `dirty`      | 待保存                  | 等待原自动保存               |
| `saving`     | 保存中…                 | 显示正在保存                 |
| `blocked`    | 正在编辑或上传…         | 等待当前交互/上传完成        |
| `offline`    | 离线 · 草稿已保留       | 明确本地状态，提供原恢复路径 |
| `conflict`   | 版本冲突 · 草稿已保留   | 提供原冲突处理动作           |
| `error`      | 保存失败 · 请重试       | 展示可操作的失败原因         |
| `deleted`    | 作品已删除 · 保存已停止 | 停止原作品写入和导出新任务   |

“导出 PNG”先 `flush()`，再以返回的 `revision` 和该次操作幂等键创建任务。等待提交、排队、生成、完成或失败分别显示。排队或生成时顶栏显示“查看导出”，关闭弹窗后仍能回到原任务。当前稿件发生溢出或保存失败，只阻止创建新任务，不影响查看已提交任务。导出结果继续使用原任务版本。完成后再次导出提交最新已保存版本。离开作品或刷新后进入新的编辑会话。成功显示原图尺寸、PNG 预览和下载，预览与下载使用同一文件。当前文档的溢出、缺字及保存问题给出具体处理入口。

## UI-10 弹层、焦点、通知和快捷键

- 对话框和抽屉用明确的可访问标题，保留对应按钮名称、焦点圈定和滚动锁。按原业务策略决定遮罩、关闭按钮或 Escape 是否可关闭。危险确认的取消优先于破坏性动作。忙碌态持续时阻止重复确认。
- 内层下拉、颜色或字体菜单在当前有效容器呈现。打开时进入弹层栈，隐藏、关闭或卸载时退出。第一次 Escape 只关闭内层，下一次才到父层。关闭归还焦点。手机弹层显示区域限制在可见视口，内容长时内部滚动。
- 画布全局 Delete、Backspace、Escape、撤销、重做在输入、可编辑节点、输入法组合和活动弹层中遵循已有拦截。普通工具按钮保持画布快捷键行为。弹层关闭后恢复快捷键，页面滚动锁回到打开前状态。
- 通知保留 id 去重、同 id 更新、重试、关闭、账号作用域。普通 4000ms，错误 6000ms，持久通知为 0。活动弹层内通知及操作按钮对键盘和读屏可达。页面级通知在弹层改变时随有效容器迁移；弹层来源卸载时关闭。账号切换清除旧通知，拒绝迟到回调和旧重试。
- 两站统一 loading、空态、错误和可用内容。需要后续操作的错误有明确重试或恢复入口，保存失败、冲突、离线、等待清理等状态有持续可见的信息。

## UI-11 管理后台的列表和任务详情

桌面导航分为“账号与作品”（概览、用户、作品元数据）、“内容资源”（背景、模板、字体、文案）和“运行记录”（导出任务、审计）。手机以顶栏按钮折叠菜单，关闭后焦点回到触发按钮，当前路由高亮。

用户、作品元数据、任务和审计桌面使用语义表格和服务端分页。每页 24 条，记录 ID 作为行键。状态、筛选和独立加载错误仍按原 API。删除造成页码超界时仅依据已返回的服务端结果回到有效页。后台作品永久删除要求已软删除并明确确认归属，清理队列和作品列表分开呈现。

导出任务以现有 `JobDTO` 表达任务 ID、作品 ID、版本、状态、创建时间和已有错误描述。桌面表格与手机摘要从同一查询派生。后台任务继续每 5 秒轮询，状态文字可表达排队、运行、成功、失败和未识别值。失败行有“查看失败原因”，详情显示当前任务元数据与已有错误。后台权限只覆盖现有管理数据，用户私有图像、源文案和下载资源仍由现有授权接口管理。 [antd Table](https://ant.design/components/table/)

## UI-12 依赖和构建边界

目标使用 antd 6。本次计划固定 `6.7.0`，与当前 React/ReactDOM 19.3.1 的 peer 要求相容。直接使用 antd 的包声明其依赖，保留现有 Lucide 图标。两站的共享路由、请求和样式来自相应共享包。编辑器和重型页面通过路由或工作区入口按需加载，登录入口的静态依赖不包含 Tiptap/ProseMirror。renderer 入口独立，仅使用文档与渲染依赖。

antd 的输入值、回调、弹层和样式以所锁版本的公开 API 为准。通过既有共享接口保护两站调用。旧 Base UI 依赖在对应业务和交互迁移通过后统一清理。图片、字体、作品模板和契约继续使用现有来源。 [antd v6](https://ant.design/docs/react/migration-v6/)

## UI-14 变更决定与交接

已确认的设计决定是深绿品牌色、作品顶部导航、共享编辑器四组属性、可收起两栏、手机分组面板和后台分组导航。后续可按本规范决定具体组件配置、文件拆分和 CSS 实现。实际行为、权限、数据归属、可访问性或验收口径需要变更时，在实施计划记录原条目、具体冲突和待用户决定的影响，得到明确决定后同步更新两份文档。

实施从用户明确开工后开始。中断后按配套计划读取当前任务、分支、未提交内容、验证结果和待决项，再恢复该任务的下一步。正文、图像、凭据和业务数据只留在其原有安全存储，记录只引用经核对的测试样本与可分享证据。
