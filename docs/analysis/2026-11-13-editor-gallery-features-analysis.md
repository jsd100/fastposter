## 2. 逐项深挖

### 2.1 ① 九宫格辅助线与开关

**已确认需求**：中间海报预览加九宫格，用户通过开关控制显示，以便在拖动文字时定位。

**建议的交互口径**：

- 画布工具区靠近「缩放」放置带可见名称的 antd `Switch`，文案用「九宫格」。开启后在画布内持续显示，拖动前、拖动中和拖动后都可对照。关闭立即隐藏。手机端保持至少 44×44px 的可操作区域。
- 建议初次打开编辑器默认关闭，并在当前浏览器记住选择。作用域建议按站点和用户保存，用户站与管理站使用同一个共享控件，各自记住偏好。同一用户在同站切换作品或刷新时沿用选择。存储不可用时，当次会话仍可开关。默认值与记忆策略属于本轮建议。
- 使用两横两竖，每条线位于海报宽度或高度的 ⅓、⅔ 处。不绘制外框。细线保持约 1 CSS 像素，采用在深浅照片上都可辨认的低对比双层处理，无出现动画。
- 当前范围是目视定位。自动吸附需要另外定义对齐锚点、阈值和退出方式。

**代码分析**：

- `packages/poster-editor/src/Stage.tsx` 的海报画布使用 `translate + scale`。建议参考 `SelectionHandles.tsx` 的舞台坐标换算，让辅助层作为画布的兄弟节点，位置随平移和缩放计算，尺寸与海报显示区域一致。层级低于选框和手柄，设置 `pointer-events: none`，并从辅助技术中隐藏装饰线。
- 拖动已经通过 `store.begin()` 与 `commit()/cancel()` 收敛为一个手势。开关属于视图偏好，不进入海报文档、编辑历史或自动保存，也无需改动拖动坐标。
- 两站都使用共享 `Editor`。导出入口与作品缩略图使用 `PosterFrame`。辅助层留在 `Stage` 内即可隔离成品渲染与文本测量。

**验收**：

1. 开关可用鼠标、键盘和触摸操作，显示状态与开关一致。
2. 开启后，两横两竖随初始适配、平移、缩放及窗口变化贴合真实海报范围。拖动和调整文本框宽度时没有误拦截。
3. 切换开关不产生撤销记录或作品修订。打开和关闭时导出同一未修改作品，像素一致。用户站和管理端模板编辑器均检查控件及手机布局。

### 2.2 ② 阴影、描边和快捷预设

`StylePanel.tsx` 会把参数写到 `block.effects`，`PosterFrame.tsx` 的 `blockCSS` 将其转换成 `text-shadow` 和 `-webkit-text-stroke`。源码能解释阴影有时看不出变化：

| 当前操作 | 可能看不到效果的原因 |
| --- | --- |
| 在默认阴影色上只调整色相 | 默认 `#00000000`，颜色选择器可以保留 alpha=0 |
| 从默认状态只调整模糊或偏移 | 阴影颜色仍然透明 |
| 只输入不透明阴影色 | 偏移和模糊都为 0，阴影正好被文字盖住 |
| 描边只改颜色 | 默认宽度为 0 |

**建议**：在「效果」面板为阴影、描边各提供一组快捷预设。入口位置沿用「预设文字颜色」的就近原则，选项用示例字显示实际效果。阴影可提供「无、柔和投影、硬边投影、发光」，描边可提供「无、亮色细描边、暗色细描边、粗描边」。移动端允许换行或在带可见标签的选择面板里展开，保留原有精确调节控件。

- 阴影预设同时写入颜色、模糊和两个偏移。描边预设同时写入颜色与宽度。关闭可用现有的透明色或零宽度表达。
- 从关闭态主动启用自定义效果时，提供一组可见初值。用户随后可精确调整透明度，包含主动设到零。打开控件或载入旧作品本身不触发写入。
- 每次预设应用是一条撤销记录，单独调参后显示为「自定义」。阴影操作不覆盖描边、文字背景色或不透明度。
- 以纯色、亮底、暗底和透明导出测试可见性。渐变交付时增加组合场景，尤其检查硬边阴影是否透过渐变字形内部。

### 2.3 ③ 连续字重 100–700

**已确认需求**：可变字体在实际支持的范围内以步长 1 调节，目标常用范围 100–700，包含比 400 更细的字重。

重新读取仓库字体文件的 OpenType `fvar` 表。Noto Sans SC、Inter 的 `wght` 轴为 100–900，Noto Serif SC 为 200–900，另外 7 个 TTF 为静态字体。Inter 沿用当前西文字体覆盖约束。

| 层 | 现状与影响 |
| --- | --- |
| 文档 | TS `schema.ts:14` 与 Go `document/validate.go:65,144` 接受 100–900 的整数。250 可以写进现有文档，历史值 900 继续有效。 |
| 字体控件 | `TextPanel.tsx:141-161` 当前按字体资源的离散 face 列字重。`prepare-change.ts` 找不到精确字重时会走既定回退。 |
| 浏览器 | `FontRegistry.ts:22-34` 把每个资源注册为单值 `FontFace.weight`。需要按实际 `wght` 范围注册可变字体，并按资源版本缓存。 |
| 字体覆盖 | `server/internal/fontfile/coverage.go:42-55` 先精确匹配同家族、同字重、同样式的引用，再读文件。因此引用标称 400 的可变文件时，即使文件支持 250，也可能得到 `MISSING_FONT`。`catalog/coverage.go` 与导出 worker 都走该检查。 |
| 导出 | `server/internal/exports/fonts.go` 也按离散字重匹配。请求在 `service.go:105-110` 就可能被拒绝，worker 和渲染器还有对应的前置校验。 |

**实施建议**：

1. 让字体能力与 `assetId + version` 对应。Go 的 `fontfile/font.go:168-188` 已能解析轴范围，可以复用。浏览器注册和 Go 覆盖、导出选择采用一致的规则，优先保留现有精确匹配，同时允许真实可变轴覆盖请求字重。继续校验字体权限、字形覆盖和实际斜体能力。
2. 在可变字体上提供滑杆及当前数值。Noto Serif SC 的滑杆实际起点为 200；静态字体保留真实离散选项，只有一个字重时显示该值。打开已有 900 字重的作品时显示实际值并保留其渲染，用户主动调节才更新文档。
3. 明确区分字体资源引用与字号样式里的字重。滑到 250 使用支持该字重的现有字体资源，同一资源无需为每个字重新增一条引用。换字体时保留目标字体支持的连续值，超出时采用可解释的回退和提示。选区混合字重、光标输入样式、粗体优先级一并覆盖。
4. 复用已有编辑手势事务，滑动时实时预览，一次拖动只生成一条撤销记录；写入显式字重时按现有规则处理所编辑范围的粗体标记。

**验收**：用仅登记 400 face 的可变字体作品，验证 100、250、400、700 的选择、保存重开、字体覆盖检查、导出入队及 worker 最终输出；比较相同字体的真实字形变化。另测 900 旧文档、Noto Serif SC 的下限、静态字体、不可用斜体、选区与整块修改。Go 的覆盖和导出测试都属于本项范围。

### 2.4 ④ 文字渐变

**已确认需求**：可调角度的线性渐变、径向渐变、给选中的一段文字单独上渐变。同一施加范围跨行时保持一个连续渐变。由选区施加的效果可与相邻的实色和其他渐变共存。

**建议的操作**：

- 在「文字颜色」选择「纯色 / 线性 / 径向」，复用 antd 的色标编辑能力，并提供线性角度或径向中心。建议色标 2–8 个，位置 0–100%，颜色保留透明度，默认径向为圆形。参数范围属于设计建议。
- 「预设文字颜色」保留当前纯色预设，增加渐变分组。选区修改遵循现有文字颜色语义：编辑态有选区时只修改选区，光标态控制后续输入，选择态可对整个文字块应用。色标拖动复用手势事务，切换纯色或撤销后恢复对应的值和选区。
- antd 6.7.0 的 [ColorPicker 渐变模式](https://ant.design/components/color-picker/) 可编辑色标，安装版本的 `color-picker/color.js` 输出固定 90° 线性渐变。角度、径向及文字渲染由 FastPoster 负责。

**数据与代码链路**：

- 建议把 `InlineStyle.color` 扩为「现有十六进制字符串 / 线性对象 / 径向对象」。线性对象存类型、角度和色标，径向对象存类型、中心和色标。每个色标的颜色继续沿用六位或八位 hex。双端校验类型、长度、有限数值、范围、顺序和未知字段，由渲染端从校验后的描述生成 CSS。
- TS 的 `poster-schema/src/{types,schema}.ts` 与 Go 的 `document/{document,validate}.go` 同步处理 `defaultStyle.color` 和 `textStyle.attrs.color`。阴影、描边、文字背景继续使用原来的纯色字段。现有不透明 JSON 传输契约可沿用，是否引入新文档版本待发布方案决定。
- `text/extensions.ts:29-34` 当前将颜色直接拼入 CSS，编辑态需读写渐变结构。`selection.ts:83-103` 需按颜色内容比较对象以识别混合状态。`Editor.tsx:593-621` 的选区、光标和整块更新路径都需覆盖。
- 编辑态 Tiptap、非编辑态 `RichText`、缩略图和导出需要一致的颜色语义。同一渐变范围内改字体、字号或字重后，可以产生多个富文本节点，渲染仍需识别这些节点共享的渐变范围。是否用显式范围标识，交由原型验证。

#### 2.4.1 历史 Chrome 实验与本轮验收口径

下表来自 2026-11-14 的历史分析记录，Chrome `157.0.8103.78`，40px 文字、460px 宽、四行，线性样本使用红、黄、蓝三个色标。结果来自 CSS 对照页和像素采样。实际项目导出与编辑态仍需验证。

| 组 | 场景 | 实测结果 |
| --- | --- | --- |
| A / B / C | 实色基线 / 块级渐变 / 块级渐变 + 子 span 设 `color:#c86445` | C 组 `getComputedStyle(span).webkitTextFillColor === rgba(0,0,0,0)`，**inline 实色视觉消失但数据仍在**。`-webkit-text-fill-color` 是继承属性 ⇒ 外层做渐变会吞掉块内所有 inline 颜色 mark |
| D | 选区级线性渐变，跨行，**默认 `box-decoration-break: slice`** | 4 行最饱和像素 R/G/B：line1 `232/38/28 → 237/124/46`、line2 `238/133/47 → 240/196/61`、line3 `223/186/75 → 97/114/170`、line4 `82/105/181 → 26/73/224` ⇒ 渐变沿**未断行的逻辑长行**连续推进，跨行不重复 |
| E | 同 D + `box-decoration-break: clone` | 每行都 `232/45/29 → 28/74/222`，**每行各自重复完整渐变**，短行被压缩 |
| F | 选区级**径向**渐变跨行 | line1 右端 `232/40/28`（红）、line2 左端 `232/38/28`、line4 `26/73/223`（蓝）⇒ 圆心被拉伸到整个跨行 bounding box，视觉近似斜向线性，**圆形语义丢失** |
| G | 选区级渐变 + `text-shadow:5px 7px 0 rgba(0,0,0,.85)` | 黑色阴影填满透明字形内部，英文行几乎全黑、渐变只剩细边 ⇒ **② 与 ④ 同时启用会互相破坏** |
| H | 选区级渐变 + `-webkit-text-stroke:2px #111; paint-order:stroke fill` | 渐变仍可见但整体压暗、笔画边缘发黑 ⇒ 可共存，但需明确「描边画在渐变之上」的语义 |
| alpha | 模拟 `transparentTextOnly`：`omitBackground` 截图 500×220 | 不透明像素 6176（**5.61%**），其余 94% 全透明；按 x 采样 `233/50/31 → 240/163/54 → 47/85/207`，**无渐变矩形泄漏** ⇒ `compose.go:9-26` 的按 alpha 合成可沿用 |
I 组补测了 `slice` 跨行时不同角度的表现。

| 角度 | line1 x30→x430 | line4 x30→x230 | 判断 |
| --- | --- | --- | --- |
| `0deg`（纵向） | `236/98/40 → 236/103/41` | `237/115/44 → 237/120/45` | **4 行几乎同一橙色**，纵向渐变被压平 |
| `45deg` | `233/42/29 → 238/126/46` | `85/107/179 → 31/76/221` | 与 90deg 几乎相同 |
| `90deg` | `233/41/29 → 238/125/46` | `82/105/182 → 26/73/224` | 沿文本流连续推进 |
J 组在同一渐变的相邻两个 `span` 交界处测得蓝色跳回红色。相邻节点样式完全相同时，ProseMirror 可合并节点；换字号、字体或字重后仍可能分开。K 组在段落层验证了 0° 纵向颜色变化，同时发现实色子节点需要显式填充色。一个段落若只使用一张渐变背景，难以表达同段多个独立选区。

| 方案 | 适用情况 | 需要验证的限制 |
| --- | --- | --- |
| 每个文字片段使用 CSS `slice` | 单行基线，或测量同一内联元素的连续性 | 跨行角度退化、径向变形、样式分段处重启 |
| 段落级渐变背景 | 验证按实际布局计算角度 | 同段多个渐变范围、实色继承、跨段连续 |
| 按选区范围计算共享坐标，与文字填充和效果分层 | 候选方案，可同时表达连续范围和局部实色 | 布局变化后的坐标更新、编辑态一致性、阴影与描边叠加、透明导出 |

**先验证的样例**：在同一段内保留纯色和两个不同渐变选区，其中一个选区跨行，局部改字号，同时使用阴影、描边和文字背景色。线性角度用 0°、45°、90° 对照，径向移动中心，验证跨行连续、相邻纯色仍可见、换字体后不重启、阴影不侵入字形，以及透明 PNG 没有矩形泄漏。历史上讨论的 `slice` 可作为对照实现。跨行连续是产品验收条件，跨行精度与渲染结构待对照验证后确定。

**兼容性**：允许旧纯色文档直接读取和往返。当前旧版 Go 和 TS 会拒绝新增的颜色对象或未知字段，旧 worker 也可能无法消费含渐变快照。建议先验证可读版本在用户站、管理站、服务端、缩略图和 worker 中全部到位，再开放新文档写入。启用后保留能读渐变的回退版本。正式发布方案需验证排队中的导出和模板文档也能往返。

### 2.5 ⑤ 卡片高亮

`apps/web/src/features/projects/ProjectList.tsx:131` 用 antd `Card hoverable` 提供作品卡的默认悬停阴影和边框反馈。背景和部分文案选择项是按钮式卡片，只有样式层能实现等效反馈。

- 建议覆盖用户站作品、回收站作品、模板、背景及文案选择，以及后台模板、背景、字体和文案列表。登录、统计等面板与加载骨架继续作为静态内容。
- 整张可点的卡片复用默认高亮。卡片内有多个独立操作时，悬停或操作获得键盘焦点时整卡有反馈，指针与焦点仍指向具体操作。背景库的已选中状态独立保留，触屏用户也能辨认。
- 使用现有 antd 默认主题的阴影、边框和焦点反馈，按当前减少动态效果设置处理过渡。优先用 `Card` 自身能力及少量共享样式。
- 验收鼠标悬停、Tab 焦点、移动端选中和长标题布局，核对卡片中的菜单与预览按钮有明确焦点、各自触发原有动作。

### 2.6 ⑥ 背景图放大预览

现有 `BackgroundPicker.tsx:251-278` 将缩略图放入选用按钮。replace 模式一次点击即替换；create 模式选中后还需点击「用此背景创建」。后台 `Resources.tsx:272-280` 用普通图片展示背景资源。

- 本批已确认覆盖用户站创建和替换背景的入口，使用 [antd Image 受控预览](https://ant.design/components/image/)。预览层覆盖视口并支持缩放。后台背景资源列表和合成海报模板预览留待后续。
- 缩略图继续用 `previewUrl`，用户打开大图时请求其版本对应的 `asset.url`。原图失败时在预览内给出失败反馈和关闭入口。
- 使用独立、可聚焦且有名称的「放大预览」入口，和选择或选用按钮并列。预览不改变当前背景，选用按钮继续遵循所在模式的创建确认或一次替换语义。
- 对话框内协调预览的层级、焦点与键盘处理。打开时焦点进入大图，第一次 Esc 关闭大图并恢复焦点，之后 Esc 才作用到背景库。筛选、滚动和已选状态在关闭大图后保持。
- 测试用户站创建和替换两种模式，检查原图按需加载、键盘关闭次序、加载失败、手机缩放及点击放大时没有选用写入。

### 2.7 ⑦ 回收站操作区溢出

回收站是 `/projects` 的列表状态。`ProjectList.tsx:147-183` 把标题和操作放在横向 Flex 容器。`apps/web/src/styles.css:63-88,115-120` 允许操作组缩到其按钮最小内容宽度以下。组内换行仅能分开两个按钮，带图标和不可换行文字的「彻底删除」仍可能超出。网格在桌面列宽接近 212px 时也能触发这个条件。本轮为源码定位，浏览器复现留待界面验证。

- 回收站卡片改为标题和元信息占整行，操作区独占下一行。按卡片实际可用宽度决定同排或上下排列。
- 保留「恢复」「彻底删除」的完整文字、危险样式、现有确认流程和键盘访问。窄屏下维持主操作触摸尺寸。
- 验收 320px、390px、现有 360px 回归场景及桌面多列逼近最小列宽的场景，加入长标题样本。分别检查每个按钮的边界落在卡片内、页面无横向溢出，恢复和彻底删除的确认行为正常。
