# FastPoster 前端组件库与页面重设计分析

日期：2026-11-05。分析基线：`d6c3d45`。本轮只新增分析材料，没有修改业务源码、依赖清单、锁文件、接口或数据库结构。

本文区分三类内容：**现状**来自当前源码和实际运行；**风险**是替换组件时需要防止的回归；**建议**是供下一轮设计讨论的判断，尚未成为获批实现方案。

## 1. 核心判断

FastPoster 适合采用 antd，但应把这次工作视为“通用界面体系迁移 + 页面信息架构重设计”。最值得改变的是控件一致性、可读性、操作层级、后台信息密度和移动布局；最值得保留的是已有海报文档、编辑事务、字体资产及导出链路。

当前组件库是 `@base-ui/react@1.9.0` 加自建视觉封装，项目尚未使用 antd。已有共享层是有利条件：不需要在所有页面分别接入新库。但共享组件已经承载业务交互契约，不能简单将名称相同的组件互换。

建议的边界：

- antd 承担 Button、Input、Select、Modal、Drawer、Form、Table、Pagination、Menu、Dropdown、状态反馈等通用界面。
- `@fastposter/ui` 承担跨应用主题、通知适配、可访问性约定和必要的兼容封装。
- `poster-editor` 保留字体预检、选区、数值事务、图层、画布与手势等领域能力。
- `poster-renderer` 和 `poster-schema` 保持独立，不引入 antd 主题、全局 reset 或组件 DOM。

这次请求明确允许重新设计布局与风格。历史文档中“保留现有布局和清新配色”“不引入整套组件库”属于前两轮的范围约束，不能作为拒绝本次 antd 迁移的依据；其中已经实现的选区、数值、通知与导出行为仍应作为回归要求保留。

## 2. 调查范围与证据边界

已检查：三应用入口与构建配置、共享包依赖、全部前端页面类型、主要 UI 封装、编辑器和渲染器、自动保存及草稿链路、字体选择、导出、永久删除、相关 IDL、现有设计/验收文档及测试配置。

已执行：antd CLI 环境和使用扫描、组件 API 查询、v5/v6 差异核对；前端类型检查、全部前端单测、强制生产构建；临时真实服务栈截图及控件/编辑/通知/导出专项浏览器回归。浏览器测试使用项目自带保护器和 `fastposter_test_*` 临时数据库，没有操作用户业务作品。

未声称完成：全部 Go 测试、完整 Playwright 套件、真实手机输入法验收、Safari/Firefox 验收、大量真实作品与资源的容量测试、迁移后包体或性能验证。本轮尚未引入 antd，所以兼容性结论是迁移可行性判断，不是已运行通过的新库集成结果。

## 3. 现有架构及迁移影响面

```text
用户站 apps/web                  管理站 apps/admin
账号 / 作品 / 回收站 / 工作区      账号 / 资源 / 元数据 / 模板编辑
          │                               │
          ├──── @fastposter/ui ─────────────┤
          │     通用控件 / 通知 / 品牌       │
          ├──── poster-editor ──────────────┤
          │     Stage / Tiptap / 历史 / 字体 │
          │                 │             │
          │          poster-renderer       │
          │                 ▲             │
          │          apps/renderer         │
          │          Chrome 导出入口       │
          │                               │
          └──────── api-client ────────────┘
                    生成路由 + 统一错误
                            │
                 Go 网关 → 核心服务
                            │
                  MySQL + 本地资源文件
                            │
                   导出 / 清理 worker
```

### 有利于迁移的部分

1. 用户作品与后台模板复用同一个 `Editor`，改造一次即可覆盖两处，但两种挂载方式都必须验收。
2. schema、renderer、editor 的职责已经分开，能重做界面而不升级作品格式。
3. 查询使用 TanStack Query，保存与编辑历史另有明确状态机，不需要为使用 antd 替换状态管理。
4. UI 已有普通/紧凑密度、字段标记、弹层标记和可访问名称，可形成渐进迁移接口。
5. 字体按资产 ID 和版本引用，模板包、预览、最终导出可继续共用原有实现。

### 应先解除的耦合

| 现状 | 直接证据 | 影响与建议 |
| --- | --- | --- |
| 后台导入用户站整份 CSS | `apps/admin/src/styles.css:1` | 后台连同登录页、作品页、编辑器的规则一起继承；应将 reset、主题、共享控件、编辑器、页面样式分开 |
| 后台复用用户站内部路由/API 文件 | `apps/admin/src/router.tsx`、`apps/admin/src/api.ts` | 可复用实现，但共享位置不应在另一个应用内部；先抽取很小的公共模块，无需同时更换路由框架 |
| 页面入口全部静态导入 | 两站 `src/main.tsx` | 登录页也承担编辑器依赖；为编辑器与后台重页面设置动态加载边界 |
| 大型页面集成状态、请求、上传和弹窗 | `ProjectsPage.tsx`、`ProjectWorkspace.tsx`、`Metadata.tsx` | 迁移时按页面拆外壳/状态/内容，保持业务 hook 和契约稳定；不进行无关的大规模重写 |
| 基础控件样式依赖页面级选择器 | `.form-field input`、`.panel-field [data-fp-input]`、`.stage-zoom .select` | antd DOM 增加包装层后规则可能作用错误；用组件 token、显式 className 和语义样式重建 |

项目当前用轻量 history/router，没有 React Router、Umi 或 Ant Design Pro。antd 的接入不要求引入这些框架，也不要求更改后端 API。

## 4. 页面与用户任务清单

### 用户站

| 页面/状态 | 当前任务与结构 | 建议重点 |
| --- | --- | --- |
| `/login`、`/register` | 左侧品牌示意、右侧表单；手机隐藏故事区 | 保留清晰登录路径，更新真实海报示例；减少纯装饰英文标签 |
| `/password` 与 reset 参数 | 修改密码、使用一次性令牌重置 | 用清晰字段反馈和密码输入；保持自动完成、最小长度、重登逻辑 |
| `/projects` | 左导航、顶栏、标题操作、搜索、作品网格 | 让作品预览和新建入口成为主体；压缩重复标题/说明/装饰占位 |
| 回收站 | 同一路由内本地状态切换 | 区分可恢复作品、不可恢复待清理任务、清理完成；不可合并成一个“删除成功”提示 |
| `/projects/:id/edit` | 工作区顶栏 + 命令栏 + 图层/画布/设置三栏 | 整理全局操作与当前对象操作；优化画布空间和设置分组 |
| 模板库 | 作品页弹窗，筛选、预览、应用、ZIP 导入 | 使用图库结构，解释“会创建新作品”；保留原比例预览 |
| 背景库 | 编辑时弹窗选择素材 | 搜索/分类固定、内容区域滚动；不同尺寸替换需继续确认 |
| 文案库 | 搜索、多级分类、文案列表 | 五级分类可考虑 Cascader/TreeSelect；保留父分类可选和全部分类语义 |
| 草稿/冲突/离线 | 独立恢复与另存流程 | 在重设计中作为核心状态设计，不仅绘制正常已保存界面 |
| 导出 | 先保存指定版本、任务轮询、最终预览/下载 | 显示真实任务阶段；关闭弹窗后能返回同一任务，不伪造百分比 |

### 管理站

| 路由 | 现有职责 | 合适的 antd 方向 |
| --- | --- | --- |
| `/admin/login` | 管理员登录，无后台注册 | Form、Input.Password、Button |
| `/admin/overview` | 用户/作品/存储/成功失败导出计数 | Statistic + 适度布局；不凭空增加趋势图 |
| `/admin/users` | 搜索、分页、禁用/恢复、一次性密码重置 | Table、Tag、Pagination、Modal；令牌仍只显示本次 |
| `/admin/projects` | 作品元数据、回收站状态、永久删除、清理队列 | Table、Select、Alert、领域确认弹窗 |
| `/admin/backgrounds`、`/admin/fonts` | 分类、上传、授权、发布/下架、版本 | 图库/字体预览 + Form/Upload/Checkbox，不强行全部改成表格 |
| `/admin/templates` | 创建/编辑/发布/导入导出模板 | 原比例图库 + 独立模板工作区 |
| `/admin/copy` | 五级分类管理、纯文本文案、发布 | Tree + 内容列表、TreeSelect、Form |

后台目前有四处原生 table，覆盖用户、作品、任务和审计；其余管理对象有真实视觉预览需求。后台作品/任务明确只提供元数据，改造时不能为了“预览体验”请求或展示用户私有正文、图片。

## 5. 视觉与布局审视

### 5.1 当前优点

当前深绿、淡绿、白底已经形成统一识别；品牌图标、主要操作、工作区布局连贯。登录页的短句海报示意贴近产品内容。编辑器的画布/文字/图层结构容易理解，桌面和手机已共用领域面板。改造可以从这些能力继续发展。

### 5.2 优先解决的问题

**可读性比换色更紧迫。** 页面与编辑器大量使用 8–11px 的说明、标签和元数据。将若干实际 CSS 色值与白色背景计算对比度：

| 色值/角色 | 对比度 | 判断 |
| --- | ---: | --- |
| `#35472e` 正文 | 10.04:1 | 清晰，可继续作为深色层级参考 |
| `#335b40` 主按钮底色/白字 | 7.75:1 | 主操作有足够对比 |
| `#849279` 弱正文 | 3.30:1 | 不适合当前小字号承载必要说明 |
| `#a2af94` 提示文字 | 2.31:1 | 很弱，应加深或只作非必要装饰 |
| `#8b9c7c` 后台导航文字 | 2.94:1 | 需要提高可读性 |

这是对指定不透明色值的静态计算，不是整站无障碍认证；禁用控件和实际叠色应单独判断。新设计应建立清晰正文、辅助文字、禁用三层，而不是让大多数内容都变淡。

**主题变量尚未成为唯一来源。** 已有 37 个 `--fp-*` 变量，但页面、编辑器和 Modules 中仍存在大量直接色值；扫描得到 232 个不同十六进制 CSS 字面值，包含透明色和装饰色，不等于有 232 种用户可辨认颜色。只调整 `--fp-green` 或 antd `colorPrimary` 都不能完成统一换肤。

**作品页的导航与留白占比偏高。** 常用导航主要是“我的作品/回收站”，却有固定侧栏、顶部路径、英文栏目名、主标题、说明和底部装饰。桌面仅两件作品时，实际作品区很小。建议把空间优先留给作品预览与搜索；是否保留侧栏应与未来确定的导航需求匹配。

**编辑器操作层级不够集中。** 当前有 65px 工作区顶栏和 57px 命令栏；图层宽 190px、设置宽 250px，在 ≤900px 时变为 150px/220px；≤680px 时两侧同时消失。中等宽度设备会经历画布明显受挤、随后布局突然改变的过程，需要独立的平板策略。

**右侧属性面板纵向过长。** 原始 250px 宽面板扣除 padding 后，两列最小 152px 的设置会自动堆叠。截图中字体、字重、字号、颜色、预设颜色、格式、段落占据很长区域，效果与几何位置更靠后。建议按“文字/段落/效果/位置”分组，优先保证高频项可见，而不是单纯缩字号挤入更多字段。

**手机编辑已有基础，但操作密度需要重新安排。** 保留画布、底部操作和设置抽屉是合理方向；字体、颜色、段落可以采用清晰的分组切换。现有单个设置长抽屉需要较多滚动。不能因桌面采用紧凑 token 就把手机点击目标一起缩小。

**手机后台导航占用过多首屏。** 390×844 的实际截图中九项导航排成三行，头部约 228px；用户表格宽约 490px，由容器横向滚动承载，整页宽仍为 390px。应描述为导航占位大和表格需横滚，而不是“整页溢出”。建议折叠菜单、固定主要操作列，或为少量字段设计摘要行。

**品牌文案与本机部署存在偏差。** 当前出现“云端保存”“使用云端版本”等说法，但产品使用本机服务和本地文件。建议改成用户能理解的“已保存”“使用已保存版本”，减少不准确的云端暗示。后台面向使用者的说明也可减少不影响决策的内部实现术语。

**后台模板编辑器尚未纳入统一模态机制。** 它使用固定全屏 `div role="dialog"`，没有通过共享 Dialog 注册层级。源码没有共享 Dialog 提供的焦点圈定/恢复与通知容器注册。重设计应明确它是独立页面还是完整模态工作区，不能只保留一个 dialog role 便认为已具备完整模态行为；本轮未对其单独完成读屏/键盘审计。

## 6. antd 版本及接入方式

当前 React/ReactDOM 19.3.1、Vite 8.3.5、TypeScript 7.0.2、Node 24.21.0、pnpm 11.25.0。antd CLI 确认项目没有 antd、dayjs、`@ant-design/icons` 的直接依赖；apps/packages 的 antd 使用扫描均为零。

建议以 **antd 6** 为目标主版本。官方说明 v6 要求 React ≥18，默认使用 CSS 变量，并已原生支持 React 19；项目的 React 版本满足前提。本轮在线组件文档显示 6.7.0，可作为具体候选，实际接入仍需核对安装包 peer dependencies 并固定精确版本。[官方 v6 说明](https://ant.design/docs/react/migration-v6/)

项目是 Base UI → antd，不是 antd v5 → v6；CLI 的 `migrate 5 6` 和 `changelog 5.29.0 6.0.0` 仅用于排查旧示例/旧 API 误用，不是可以自动完成本项目迁移的 codemod。

建议共享 `UIProvider` 在两站分别挂载 `ConfigProvider` 与 antd `App`，统一中文 locale、主题、密度、弹层与消息实例。通知通过已有适配层调用上下文内实例，避免页面零散使用静态 `message.xxx`/`Modal.xxx` 导致主题和上下文不一致。[主题说明](https://ant.design/docs/react/customize-theme/)、[App 说明](https://ant.design/components/app/)

主题默认、编辑器紧凑局部主题、触摸尺寸应分别考虑。使用 component tokens 和语义 `classNames/styles`，不要依赖深层 `.ant-*` DOM 结构。若调整 CSS cascade layer/reset，应显式定义导入和覆盖关系。[样式兼容说明](https://ant.design/docs/react/compatible-style/)

已有 Lucide 图标可以作为 antd 的图标内容继续使用；换组件库不强制重做图标系统。若选择直接使用 Ant Design Icons，应采用与 antd 6 匹配的版本。暂不建议同时加入 Pro Components、第二套移动组件库和新的路由框架。

## 7. 组件迁移矩阵

| 现有实现 | antd 对应方向 | 需要保留或转换的契约 | 风险 |
| --- | --- | --- | --- |
| Button / IconButton | Button | `busy → loading`，仍禁用重复操作；保留 accessible name；原生 `type` 要转成 `htmlType` | 中 |
| TextInput / Textarea | Input / Input.TextArea | `bare` 转为明确 variant/页面布局；label、ref、自动完成和焦点不丢失 | 低至中 |
| FormField | Form.Item + 输入组件 | required/minLength/maxLength、hint/error 关联；明确由 Form 或本地 state 单方控制值 | 中 |
| Select | Select | `onValueChange → onChange`、数字/字符串值、空分类、自定义显示、色块、弹层容器 | 中 |
| Combobox / FontPicker | 可搜索 Select + 字体领域组件 | 分组、搜索、高亮预览、禁用原因、候选校验、迟到结果失效；预览不写文档 | 高 |
| NumberField | InputNumber + 数值领域适配 | 原始草稿、混合值、Escape、Enter、IME、外部撤销、动态边界与事务 | 高 |
| Dialog | Modal | 条件挂载、关闭策略、初始/返回焦点、Tab 限制、滚动锁、嵌套 Escape | 高 |
| BottomSheet | bottom Drawer 或共享移动面板 | 安全区、visualViewport、抽屉内 Select、内容滚动、关闭焦点 | 高 |
| Tooltip | Tooltip | 单一按钮、不嵌套 button；触发器转发 ref/事件；禁用按钮的可发现说明 | 中 |
| ToggleButton | Button / Segmented 等 | 保留 `aria-pressed`、独立格式开关和互斥对齐语义，保留选区 | 中 |
| NotificationsProvider | message / notification 适配 | id 更新、错误去重、persistent、retry、scope generation、卸载清理 | 高 |
| Status | Alert / Spin / Result 等 | 区分加载、提示、错误、持续阻断；不能全部变为几秒后消失的消息 | 中 |
| 原生 details 作品菜单 | Dropdown + Menu | 打开/关闭、键盘导航、移动端操作，继续触发现有领域动作 | 中 |
| 原生文件输入 | Upload / Upload.Dragger | 仍复用现有上传客户端、cookie、错误解析和真实文件限制 | 中 |
| 原生颜色输入 | ColorPicker（可选） | schema 六/八位 hex、透明色哨兵、选区应用与撤销；不能写入组件对象 | 高 |
| 原生 checkbox | Checkbox / Switch | “保存后发布”和“立即发布/下架”的生效时机不能混淆 | 低 |

| BrandIcon / PosterThumbnail | 保留领域组件 | 品牌资源与作品真实比例、资产版本，不由通用 Card/Image 重建排版 | 低 |

### 容易遗漏的 API 差异

**按钮提交类型：** 现有 `Button type="submit"` 是 HTML 属性，antd 的 `type` 表示视觉类型，HTML 提交使用 `htmlType`。直接替换 import 会破坏登录、密码、素材等表单。现有“普通按钮不提交表单”的测试应继续保留。[Button API](https://ant.design/components/button/)

**数值输入：** 当前 antd InputNumber 已有 `mode="spinner"`，无需先假定只能提供右侧上下箭头；外观上值得优先验证。但 `changeOnBlur` 默认行为、空值、formatter/parser、步进回调，不等价于本项目的草稿与编辑事务。`onStep` 是步进事件，不能直接当成长按开始/结束协议。先用当前数字输入测试做一个隔离验证，再确定适配方式；不要为了快速迁移删除现有语义。[InputNumber API](https://ant.design/components/input-number/)

**字体高亮：** 当前 Select 文档提供 `onActive`，可作为键盘/鼠标高亮预览的候选；还需验证禁用项、分组、虚拟滚动和关闭后的清理。不是仅增加 `showSearch` 就完成字体选择器迁移。在线文档与 CLI 的个别签名/弃用信息存在粒度差异，实现时以固定版本类型与实际运行核对。[Select API](https://ant.design/components/select/)

**上传：** 不能直接给 Upload 一个默认 `action` 便绕过 `apiClient.upload`。需要保留原先 FormData、统一错误、取消/重试，以及背景更换 Promise resolver 的完成/取消语义。

**ref 和表单控制：** 现有封装暴露部分原生 DOM ref，antd 对应组件通常暴露自己的 ref 接口，不能只靠类型断言维持兼容。使用 `Form.Item name` 后也不能同时留下另一套独立受控值作为事实来源。迁移时逐一核对调用者的 focus、节点访问、value 和提交读取方式。

## 8. 必须保护的行为边界

### 8.1 编辑历史与数值草稿

当前 `store` + `DocumentHistory` 统一处理文字、拖拽、宽度、样式等历史；Tiptap 撤销快捷键已转交同一 store。数值 stepper 的一次按住/松开通过 `onInteractionStart/End` 形成一条历史，同时阻止交互中自动保存。

`NumberField.tsx` 不是普通数字外壳：允许清空、`-`、未完成小数，非法值不写文档；Enter 校验，Escape 恢复进入时值；支持混合字号从目标首字样式开始步进、全角数字规范化、边界和 pointercancel 停止长按。

迁移验收必须同时证明“显示值正确、文档值正确、一次撤销正确、保存时机正确”。只测试输入框 value 不够。

### 8.2 选区、字体与颜色

选区分为整块、范围、光标插入样式三种。面板按钮通过 pointer 处理和选区快照避免丢失 Tiptap 选区。字体选择先准备候选文档、加载相同版本字体、检查目标文字覆盖，再原子应用；过期响应不能写入另一选区或另一账号/作品。

保留内置中文/西文限制、实际字重和斜体能力，不因换库伪造粗体/斜体。字体名称和 UI 字体也必须分开：界面换字体不应改变历史作品字面或导出结果。

颜色同时存在六位 RGB 与八位透明 hex，effects 使用 `#00000000` 表示透明。若换 ColorPicker，需明确 alpha 开关和序列化，不要让模型出现 HSB 对象、CSS 非 hex 字符串或无意丢失 alpha。

### 8.3 弹层与快捷键

`keyboard.ts` 目前通过 `[data-fp-popup]` 和 `[data-fp-overlay]` 判断弹层是否打开，另检查 input/textarea/select/contenteditable/combobox。antd 替换后，标记若丢失，窗口级 Delete/Backspace/Escape/撤销可能在弹层中继续作用于画布。

建议统一显式弹层状态/注册机制，兼容期继续输出所需标记；不让业务层依赖具体库私有类。验证菜单先关、父 Modal 后关，滚动锁解除、焦点返回正确，并确保 Portal 的 React 冒泡不进入 Stage 手势。

当前 z-index 分散在 60/80/90/120 与画布局部 100001。不能仅比较数值大小，因为 Stage 有 `isolation` 形成局部堆叠上下文。新 Modal/Drawer/Select/notification 必须在真实容器下验证；不可用全局加大 z-index 解决所有问题。

### 8.4 通知

已有通知 store 对账号切换递增 generation，旧异步操作无法投递到新账号；同 id 更新、persistent 错误、重试动作和组件卸载关闭均已有测试。当前通知 Portal 会跟随最上层已注册模态，保证模态内可见和可访问。

建议保留 store 与业务 hook，替换显示 sink。短成功反馈可用 message；带动作/持续故障可用 notification 或内联 Alert。两者分工与时长属于设计决策，不能用默认静态 message 取代全部现有行为。

### 8.5 保存、导出和删除

保存状态有 saved/dirty/saving/blocked/offline/conflict/error/deleted；本地草稿、版本冲突和 IndexedDB 删除屏障不能因界面简化消失。导出依赖 flush 最新文档、指定 revision 与幂等键；弹窗关闭不取消后台任务，预览与下载为同一 PNG。

永久删除先撤销作品可访问性，再异步清理独占资源；回收站恢复和不可恢复删除不能合并为一个操作。后台确认归属的复选框、默认焦点在取消、完成/等待重试的分别反馈都需保留。

### 8.6 文档与最终图片

当前 schema 限制画布单边 ≤8192、总像素 ≤4000 万、文档 ≤2 MiB、文字块/字体引用各 ≤100、单块文字 ≤10000 字符；位置、宽度、段落、效果都有约束。UI 某些效果范围比 schema 更保守，不能误把 schema 最大值自动扩展为新界面范围。

预览缩放只影响视图；文本框变宽只改变换行；换背景按比例调整位置和宽度，字号不变。`apps/renderer` 使用 `PosterFrame` 生成透明文字层，worker 再完成 PNG 输出。antd reset 或主题不能进入该渲染根；历史作品换库后应使用同一字体版本、换行和自然高度。

这是构建工具输出的十进制 kB，不是 HTTP 实测传输和首屏加载时间。两站均提示主 chunk 大于 500 kB。代码可确认全部页面和 Editor 静态导入；尚未做依赖体积归因，不能断言每个库分别占多少。

迁移建议：

1. 编辑器、后台模板编辑器和重管理页面采用动态加载；登录、作品列表应有独立轻量边界。
2. antd 按需使用，先保留默认受支持的样式方案；没有测量前不为减包提前加入全量 CSS 或复杂静态提取配置。
3. 字体继续按需加载与请求合并，不为界面品牌一次下载全部中文字体；预览候选不批量加载整个库。
4. 对比迁移前后的首屏请求、gzip 包体、编辑器就绪时间、字体请求、面板输入和画布手势，而不只看总 dist 大小。
5. renderer 当前源码没有引用 UI/editor，虽然 package.json 声明了多余工作区依赖；实际产物应继续保持不混入 antd。

## 10. 重设计方向：供下一轮讨论

以下是基于产品和当前问题的建议，不是已确认的最终风格。主张以“清晰的海报工作台”为方向：作品本身承担视觉表现，界面安静、可读、操作直接。后台和创作界面共享品牌与基础组件，但使用不同布局密度。

### 可比较的三条路线

| 路线 | 价值 | 代价 | 判断 |
| --- | --- | --- | --- |
| 全站采用标准后台式布局 | 统一快，后台最合适 | 作品图库与画布可能像管理表单 | 可用于后台，不宜套满创作界面 |
| 以作品为中心的创作工作台 | 海报、模板、短句是视觉主体，适配产品核心 | 需要专门设计图库与编辑器布局 | 推荐作为总体方向 |
| 更强的作品展览/杂志式页面 | 登录和展示辨识度强 | 高频编辑容易被装饰和大留白拖慢 | 可用于品牌展示局部 |

这不是保留旧配色的决定：目前以既有品牌绿作为可比较起点，下一轮可整体换色。重点是语义色与中性内容建立区别，token 命名宜使用 accent/text/surface 等角色，避免继续把所有语义绑定在 `green` 名称。

## 11. 迁移路线与工作量分布

推荐渐进迁移，但按完整用户流程交付，避免长期维护两套同名控件。共享包装器只保留已有业务价值，普通 Table/Menu 等不必为了统一再完整包一层。

| --- | --- | --- |

| 6. 编辑工作台与收尾 | 桌面/平板/手机布局、设置分组、CSS 清理、移除 Base UI | 视觉基线、完整 E2E、几何/字体/导出一致性和包体对比完成 |

整体复杂度为较大的前端改造，最难的部分是数值/选区/弹层/通知契约，而不是 101 处 Button。通用表单为低至中等复杂度，后台信息组织和图库为中等，编辑器及移动模式为高复杂度。设计目标尚未确定，不宜据源码行数承诺工期。

不建议先全局替换 import 再修错误；也不建议仅把旧封装换成 antd 内核便结束，因为旧布局和样式耦合会完整保留。最合适的是稳定领域状态、迁移共享行为、逐个重做页面结构。

迁移时，应将测试分成三类：

- **行为契约继续保留：** 数值草稿/长按/撤销、选区保持、字体预检、Modal 焦点/滚动、通知去重与账号隔离、导出最新 revision、永久删除屏障。
- **实现选择器可以替换：** `.select` 内部结构、`data-fp-*` 的样式钩子、Base UI DOM。优先使用 role/label 和稳定领域标记，避免把 antd 私有 DOM 固化成下一轮约束。
- **旧视觉断言需要有意更新：** 当前测试硬编码绿色焦点 RGB、下拉文字/箭头内边距。重设计可改变颜色和尺寸，但不能删掉“有清晰焦点”“整行可点”“不溢出”的意图。

`ui-baseline.spec.ts` 是按开关启用的截图采集器，没有 `toHaveScreenshot` 比对，并不自动阻止视觉回归。现有单测主要运行于 Node，部分组件测试只验证服务端静态 HTML，因此不能替代浏览器焦点、输入法和触摸行为测试。

后续验收至少覆盖桌面、平板、390px 手机与更窄手机；字体/背景不同尺寸、长标题、空/错/加载/离线/冲突/删除状态；缩放后拖拽距离与文本自然高度；Chrome 最终 PNG 与当前字体/颜色/换行。Go 和契约检查按实际改动范围执行；不要把前端 `pnpm verify` 视为已包含 Go/E2E。

## 13. 下一轮需要确定的设计决策

1. 最主要要改善的真实操作：制作效率、视觉质感、后台维护，还是移动编辑；它决定首个原型选哪一条流程。
2. 是否延续品牌绿，还是整体更换视觉识别；本报告的 token 只是候选。
3. 作品页继续保留常驻侧栏，还是改为更轻的导航；目前只有作品与回收站，不应为未确认功能预留大量空导航。
4. 编辑器是否允许图层/设置收起或调整宽度；平板优先保留哪一侧，手机高频工具如何分组。
5. 后台与创作界面是否使用不同密度；建议共享基础 token，分别设计布局。

这些问题影响设计，当前分析不依赖立即回答。下一步适合产出代表页面的可比较设计稿，确认完整交互和视觉后再制定实现计划。
