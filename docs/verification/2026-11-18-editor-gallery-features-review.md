# 编辑器与画廊功能代码审查

审查范围 `4c3662a..763279f`，基线为七项需求的设计与实施计划提交。以当前分支的 86 个变更文件为准，后台背景大图和模板成品放大按用户确认留在本批范围之外。审查覆盖用户站、管理端模板编辑、共享编辑器、渲染器、TS/Go 文档及资产验证、自动保存、导出 worker 和测试。

**结论：需修复后再通过。** 首次保存渐变后的撤销会导致作品无法继续保存。粘贴、局部编辑、渲染和字体交互各有可独立触发的缺陷。九宫格的视图隔离、回收站拆行、背景预览与选用分离、效果预设的整组更新值得保留。

## P1 · 保存与数据兼容

**1. 首次保存渐变后撤销，云端拒绝用户继续编辑。** 在 v1 作品设置渐变，等待保存成功，点「撤销」后再保存。真实浏览器收到 422。编辑器把协议升级和样式写入放进同一条历史，撤销恢复整个 v1 快照，云端已经保存 v2 并正确拒绝降级。后续普通编辑仍基于 v1，导出前 flush 也会卡在保存。现有富文本用例在首次保存之前撤销。项目和模板的写入路径都应覆盖这个状态。应使协议版本在已成功写入 v2 的编辑会话中单调增长，允许撤销回仅有纯色的 v2 文档，并覆盖保存请求在途时撤销。位置见 `packages/poster-editor/src/Editor.tsx:650`、`packages/poster-editor/src/store.ts:306`、`server/internal/document/write.go:26`。

**2. 默认关闭的服务端开关能接受一类前端无法读取的文档。** Go 对渐变 JSON 使用大小写不敏感的结构体解码，写入开关却按原行内属性 map 的精确键判断是否含渐变。隔离 Go 探针确认该差异会让默认关闭的写入策略接受一个含行内渐变的 v2 对象，序列化后仍保留 TS 会拒绝的字段名，导致编辑器和导出无法重读。开启写入时，省略必填圆心或把色标位置设为 null 也会经 Go 解码为零并通过校验。另一个双端差异是同组 0.1° 和 360.1° 的归一化结果。应让 Go 严格解码并统一生成规范化表示，再让写入门和范围校验直接消费该表示。位置见 `server/internal/document/document.go:78`、`server/internal/document/write.go:48`、`server/internal/document/validate.go:242`、`packages/poster-schema/src/schema.ts:16`。

## P2 · 用户可见行为或兼容回归

**3. 粘贴渐变进入普通作品后生成不可保存的文档。** 真实浏览器将有效渐变片段粘贴到 v1 作品后，画布已有渐变标记，但保存返回 422。版本升级只在面板 `apply()`，Tiptap 的粘贴和普通文字更新未经过它。粘贴解析还给每个 HTML span 独立生成 ID。同一个渐变内含不同字号时，一次粘贴会把它切成多个渐变。现有用例粘贴到已经有渐变的作品，只检查一个 span 的 ID。应在可信粘贴入口校验色值，按一次粘贴的源范围建立映射，并在同一个事务中处理版本和写入开关。位置见 `packages/poster-editor/src/text/extensions.ts:38`、`packages/poster-editor/src/text/RichTextEditor.tsx:158`、`packages/poster-editor/src/Editor.tsx:650`。

**4. 修改已有渐变中一部分文字，会制造同 ID 不同参数。** 先给整段文字加渐变，再选其中几个字改角度、位置或色标。颜色面板保留原范围 ID，`setMark` 只写选区，剩余文字或块默认色仍是旧参数。两端校验都会拒绝这个文档。分别对两个选区用不同渐变预设也会出现同样的冲突，因为预设固定使用 `rangeId: "preset"`。已有测试只覆盖局部换纯色和主动传入不同 ID。应在建立新作用范围时统一分配 ID，同一手势内稳定使用。整块写入的默认色和行内标记应使用同一份已分配的 patch。位置见 `packages/poster-editor/src/panels/TextColorField.tsx:46`、`packages/poster-editor/src/panels/gradient-presets.ts:18`、`packages/poster-editor/src/Editor.tsx:638`、`packages/poster-schema/src/schema.ts:225`。

**5. 切换线性和径向会生成非法对象或删掉已有色标。** 面板有两个类型选择器。用「颜色类型」把线性改为径向，代码只换 `type`，仍带 `angle`，且没有 `centerX/centerY`。真实浏览器看到「圆心 X %」无初值，双端严格结构会拒绝保存。用另一处「渐变类型」切换时结构有效，但只取前两个色标，用户原有第三至第八个色标直接消失。只留一个配置入口，按完整字段构造判别联合，切换时保留全部色标。位置见 `packages/poster-editor/src/panels/TextColorField.tsx:48` 和 `:367`。

**6. 编辑器画布和导出的渐变按不同坐标渲染。** 退出文字编辑时，`TextBlock` 渲染 `RichText`，既未传入 `defaultStyle`，也未应用共享背景坐标。真实浏览器验证相同渐变标记在编辑态有计算出的 `background-size`，退出后变回 `auto`。因此跨样式 span 会重新起色，只有默认渐变且无行内颜色的有效 v2 文档可能出现透明字。编辑态与缩略图路径还把 `getBoundingClientRect()` 的缩放后尺寸直接写回 CSS 本地像素，只有比例 1 时坐标一致。富文本 effect 的依赖也只有 `block.content`，文本框宽度、行高及字距变化没有触发重测。建议让三条入口共用渐变布局边界，用本地像素测量或按变换换算，并测试缩放、重新断行及保存前后的实际色序。位置见 `packages/poster-editor/src/TextBlock.tsx:32`、`packages/poster-editor/src/text/RichTextEditor.tsx:259`、`packages/poster-renderer/src/gradient.ts:96`、`apps/renderer/src/main.tsx:36`。

**7. 渐变与硬边阴影组合会把字形内部盖黑。** 渐变使用 `background-clip: text` 和透明字色，`blockCSS` 继续让阴影继承到同一个绘制层。宿主 Chrome 的同款 CSS 隔离对照里，14,007 个原本不透明的彩色字形像素中，有 10,945 个在打开 3px 硬阴影后变为黑色。原型证据验证了字形外 alpha，但缺少对同一字形内部颜色保留的断言。应分离阴影、描边和填充，并用真实编辑与导出在字形内外分别采样。位置见 `packages/poster-renderer/src/PosterFrame.tsx:33`、`packages/poster-renderer/src/RichText.tsx:15`。

**8. 普通文字颜色按钮始终显示黑色。** 浏览器里选红后，实际字色是 `rgb(255, 0, 0)`，颜色按钮仍显示 `#000000`。面板将所有字符串色值替换为默认值，而旧实现只对混合态使用默认值。这也让用户重新打开色板时从黑色开始。现有 E2E 只检验文字实际颜色。位置见 `packages/poster-editor/src/panels/TextPanel.tsx:255`。

**9. 细字重后加粗，字体检查成功但无法发起导出。** 可复现顺序是思源黑体调到 100 或 250，选择一个字点「粗体」，保存并导出。真实浏览器中 `/fonts/check` 返回 200，导出返回 422。编辑器按目录中存在名义 700 放行，覆盖检查能用名义 400 可变文件渲染 700，导出入队却对粗体标记强制要求精确的 700 引用。应让粗体、斜体、覆盖检查和导出复用同一套字形能力选择规则。位置见 `packages/poster-editor/src/panels/TextPanel.tsx:334`、`server/internal/fontfile/coverage.go:51`、`server/internal/exports/fonts.go:45`。

**10. 浏览器把不同字体文件注册成相同描述符，且同一资产的不同版本共用 CSS 家族。** `FontRegistry` 循环每一个来源时却用 alias 的字重和样式登记来源字节。隔离执行当前模块并记录真实字体字节对应的 `FontFace` 参数时，Arial 普通、粗体和斜体三个文件都被注册进同一 normal 400 槽位。可变来源也把范围写到所有 alias，导致同家族静态文件被登记为可变。不同版本 URL 即使分开缓存，仍共享 `fp_<assetId>`，同屏不同版本会竞争。应把来源字节、真实样式与注册范围绑定，按精确版本组织 CSS 别名。位置见 `packages/poster-renderer/src/FontRegistry.ts:72` 和 `:92`。

**11. 滑杆提交会误删其他文字仍依赖的字体引用。** 变更字重时扫描全文的显式 `fontId` 并过滤所有文档引用。既有粗体/斜体标记可以依赖没有显式写入所属节点的同家族引用。假如另一个文字块仍有这样的斜体，从当前块调字重仍会删掉其引用，而字体检查探针只覆盖本次选区。保存后会失去原样式或导出失败。先保留既有引用；如需裁剪，按全文最终实际需要的字形计算。位置见 `packages/poster-editor/src/fonts/prepare-change.ts:288` 和 `:321`。

**12. 创建背景入口的第一次 Escape 偶发未关大图，原图失败时没有状态提示。** 创建模式首轮在第一次 Escape 后仍有两个 dialog，该用例随后连续复跑 3 次通过。隔离的 320px Chrome 验证也复现了打开后立即按 Escape，退场 class 持续至超时。同批原图失败用例和替换模式通过。当前实现把全局 Escape 交给打开预览后的被动 effect，这是首帧时序风险，尚未单独确认该监听器就是失败原因。另外，用 `Image.style` 只隐藏了内部 img，Ant Design 的预览包装仍生成无名的键盘焦点，独立浏览器用例确认 Tab 可以落到 0×0 的包装节点。原图返回 500 时大图显示为空白，页面没有错误反馈。预览关闭焦点通过标题关联，同名资源也可指向错误卡片。建议在正常的弹层管理中注册预览，并用明确的资源版本和打开按钮节点恢复焦点。修复时重复覆盖快速按 Escape、Tab 顺序、同名卡和原图失败提示。位置见 `apps/web/src/features/catalog/BackgroundPicker.tsx:77`、`:304`、`:326`。

**13. 可变字重面板缺少实时预览，混合选区显示错误。** 滑动期间只更新控件内部数字，鼠标松开才改变字形。相同字体中 250 和 350 的混合文字显示为 400。包含同家族名义 400 与 700 引用时，混合的 `fontId` 进一步导致家族为 undefined，滑杆消失。直接执行 HEAD 的换字体逻辑还复现了从 250 切到尚未加载能力的思源宋体时降到 400，预先加载同一文件后可保留 250。请求失败后的重试也丢弃 `requestedWeight`。应把草稿预览和一次提交分开，保留混合状态与原请求。位置见 `packages/poster-editor/src/panels/TextPanel.tsx:57`、`:157`、`:198`、`packages/poster-editor/src/fonts/useFontChoice.ts:163`。

## P3 · 需求覆盖与维护风险

- 管理端九宫格存储作用域固定是 `admin:template`，同浏览器更换管理员仍沿用前一个人的设置。用户站用例只验证普通账号。320px 的实测中，点击「九宫格」标签文字能开关辅助线，却会进入舞台的拖动分支并取消当前文字选中。直接点击 Switch 正常。位置见 `apps/admin/src/features/templates/TemplateEditor.tsx:357`、`packages/poster-editor/src/Stage.tsx:319`、`:438`。
- 背景卡及用户站文案卡没有接入共享整卡高亮。背景的选择按钮有自身反馈，“放大预览”获得焦点时整卡无统一反馈。现有高亮 E2E 只测作品和回收站。位置见 `apps/web/src/features/catalog/BackgroundPicker.tsx:281`、`CopyPicker.tsx:168`。
- 阴影、描边预设的分组和一次撤销符合设计。阴影的关闭态判断只匹配「透明黑色加三个零」，点「设为透明」后保留旧偏移，再选「自定义」可能没有入口重新启用。应根据实际可见性区分关闭态，保留用户显式设为透明的行为。位置见 `packages/poster-editor/src/panels/StylePanel.tsx:134`、`:147`、`effect-presets.ts:100`。
- 通用数值控件把原来的透明度整数百分比改成直接乘 100。挂载 0.29 或输入 29 后，按当前 JS 浮点转换与 NumberField 回填会显示 `28.999999999999996`。透明度应恢复整数百分比转换。位置见 `packages/poster-editor/src/panels/StylePanel.tsx:102`、`:197`。
- 字体检测缓存按请求字重存储整个字体 face。相同 17 MiB 的思源黑体文件有四个字重请求时就超出当前 64 MiB 缓存预算，长文档会反复读取和解析。worker 也先 `Inspect` 再通过 `CheckDocument` 读文件。缓存应按不可变资产版本存真实字体能力，字重只作选择参数。位置见 `server/internal/fontfile/coverage.go:64`、`server/internal/exports/worker.go:129`。
- 自定义字体兼容需覆盖旧版已接受的宽轴和斜度轴。当前 `Inspect` 会拒绝最大轴值超过 900 的文件，即使请求 400 完全合法；`ital` 跨 0 到 1 时压成单一 italic，`slnt` 范围包含 0 时也不再保留旧的可用性。TS 也丢弃越过编辑器区间的轴。位置见 `server/internal/fontfile/font.go:219`、`packages/poster-renderer/src/FontRegistry.ts:57`。
- 发布记录里的 `671c6e4` 标为只读，但该提交允许 API 保存 v2，渲染器还没有渐变绘制。当前发布文档只写开关，没有写清最早可回退版本和旧 worker 换出顺序。旧任务兼容测试只做 JSON 往返，fixture 的 SHA 是占位值，无法证明真实 worker 消费。已开放写入时，回退需要使用已支持渐变读取和渲染的部署版本。位置见 `README.md:260`、`server/internal/exports/snapshot_compat_test.go:14`。
- 改色标位置时可以让下一个色标落在前一个之前。控件保留倒序数字，TS 和 Go 均未拒绝，Chrome 会钳制实际绘制位置，面板输入与画面不一致。应保持有序，同时允许相等位置表达硬边。位置见 `packages/poster-editor/src/panels/TextColorField.tsx:155`、`packages/poster-schema/src/schema.ts:18`。
- 关闭渐变写入时导入含渐变的模板包会先上传背景，随后在创建项目或模板时被拒。失败的导入留下待 GC 的素材副作用。可在上传前检查文档写入能力，或把失败补偿纳入导入流程。位置见 `server/internal/templates/service.go:141`、`:155`、`:169`。
- 颜色与字重滑杆将 `aria-label` 传给外层，宿主 Chrome 的无障碍树显示无名 slider。使用组件的 handle 命名接口，并在测试里从角色名称定位。位置见 `packages/poster-editor/src/panels/TextPanel.tsx:74`、`TextColorField.tsx:100`。

## 修复与复验

审查发现对应的修复已在当前工作区复验。首次保存渐变后撤销会保留已发出的文档版本。剪贴板粘贴按源范围分配 ID、校验渐变字段，并继承目标作品字体来处理缺少引用的片段。修改选区、切换类型或色标位置后可以保存重开，颜色回显与实际文字一致。

- 画布、缩略图与导出共用渐变绘制。实际 Chrome 的导出像素用例覆盖跨行方向、独立纯色、透明区域，以及开启硬边阴影前后的字形颜色。编辑器用例覆盖修改对齐后重新测量、同一面板内切换选区。
- 字体按资产版本和实际字重范围注册。覆盖检查与导出共用候选规则，调字重保留仍在使用的引用。浏览器验证拖动时的即时预览、一次撤销、静态字体限制，以及单一可变字体引用的细字重加粗导出。
- 背景大图验证创建与替换、原图错误、Esc 与焦点恢复。九宫格验证账号隔离、手机点标签和导出像素一致。卡片高亮与窄回收站操作区复跑通过。效果面板验证预设、透明后的重新启用和整数百分比。
- Go 与 TS 使用一致的渐变字段校验。模板包会在上传前检查写入策略。真实 worker 测试消费了旧队列快照，并验证旧渲染产物会拒绝新快照。渐变启用与回退步骤见 [本地部署](../../deploy/local.md#渐变文档升级与回退)。

## 2026-11-19 · 渐变面板与卡片交互重设计

文字颜色通过同一入口编辑纯色、线性和径向渐变。线性方向盘支持拖动和键盘微调，径向中心支持直接定位。渐变条、明确命名的预设、当前色标以及画布实时反映颜色变化。结束操作仍收敛到一条编辑历史。Esc 可以先关闭取色器，再取消整个颜色手势，光标后的待输入样式也会恢复。

用户站创建和替换背景都使用可直接打开大图的 antd 图片封面。缩略图和原图按各自地址加载。图片预览不提交选择，原图失败可退出并返回原焦点。回收站和后台背景卡片通过紧凑描边按钮降低操作区的视觉权重，保留删除确认和发布冲突恢复。

- `pnpm verify` 通过，36 个测试文件、248 个单元测试、8 个工作区构建通过。Go 包测试、定向格式检查与 `git diff --check` 通过。
- Chrome 共复测 23 个相关用例。富文本 13 个覆盖保存重开、光标取消、局部选区、撤销和 PNG 导出。其余用例覆盖手机色标、创建和替换背景、回收站、后台发布冲突及减少动态效果。
- 渐变面板和回收站实测 1440、1024、768、390、320px。320px 另用触屏上下文验证重叠色标可分别选中、输入字号为 16px，以及回收站操作的 44px 点按区域。
- 完整方案见 [渐变与卡片交互重设计](../superpowers/specs/2026-11-19-editor-gallery-interaction-redesign.md)。

本轮验证通过 `pnpm verify`（246 项 Vitest，8 个构建任务）、Go 包测试、三个前端入口依赖边界检查，以及 42 个不同的定向 Playwright 用例。受保护的 MySQL 集成与真实 Chrome 导出共 73 项通过、2 项按开关跳过。临时浏览器栈通过 Playwright 单独启动。未运行完整 Playwright 套件、真机浏览器和上限压力测试。
