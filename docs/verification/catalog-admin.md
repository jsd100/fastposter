# 公共资源与管理后台验证

后台使用独立 React 应用，路由 `/admin/overview`、`users`、`projects`、`backgrounds`、`fonts`、`jobs`、`audit`。每个管理 RPC 在 core 解析会话并校验 admin；前端不提供角色选择。人用管理员通过已实现的 admin-cli 创建，不设默认密码。浏览器测试中的 admin-e2e 仅存在于独立的 fastposter_test_* 数据库。

作品管理使用独立 Thrift ProjectMetadataDTO，仅传名称、归属、尺寸、版本、时间；没有正文、背景文件或字体内容。管理任务列表不提供他人的下载入口，也不转发可能包含私有文字的缺字详情。审计只记录动作与目标 ID。

字体原文件支持 TTF、OTF、WOFF2，最大 20 MiB；标准化 SFNT 最大 30 MiB。字体解析读取 OS/2 和 fvar，核验实际字重和正常/斜体。WOFF2 预先限制目录表总长，并以有界 Brotli 输出计数验证，再交给转换器，避免仅信任头部长度。转换器锁定版本及来源：[tdewolff/font](https://github.com/tdewolff/font)。

缺字检查使用实际字体 cmap；编辑器提示缺字并阻止正式导出，worker 在渲染前再次检查，避免系统字体悄悄补字。解析缓存按请求保留最多 64 MiB，源文件仍从已授权的不可变版本加载。

真实检查已覆盖：

- 发布共享背景→用户选用→下架→旧作品读回并导出。
- 上传实际 500 字重字体→用户可选择→中文缺字提示→更换为该字体支持的文字→下架后旧作品继续导出。
- 普通用户伪造管理请求 403；管理作品数据无 document/textBlocks；下架版本引用不被删除。
- 实际磁盘统计包含管理根目录下的原图、标准化文件、预览、字体、导出和临时/孤立文件，跳过符号链接；没有把同一个物理 key 的原图/标准化引用重复相加。
- 内置字体初始化为资源登记引用，重复启动不重新发布已经下架的字体。

资源版本只追加。下架影响新的浏览选择；已有作品通过明确版本引用读取。删除被引用的素材会返回冲突并提示下架，不提供直接物理删除入口。
