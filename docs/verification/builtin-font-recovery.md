# 内置字体运行时副本恢复

日期：2026-11-04。

## 原因与修改

`assets/fonts` 的字体、清单及授权已纳入 Git；`var/data/fonts` 是数据库存储键对应的运行时副本。此前启动代码只检查 assets 记录，记录存在就跳过；运行时目录缺失时不会自动补回文件。

核心服务现在检查清单所列内置字体的全部资产版本：

- 现存文件核对数据库保存的大小和 SHA-256。
- 缺失文件只使用仓库中完全匹配该大小和哈希的内置源文件恢复，沿用原存储键。
- 使用 FileStore 的不可覆盖写入，在文件已经被其他恢复操作创建时重新校验。
- 不新增版本，不修改作品引用、当前版本或资源上下架状态。
- 历史版本的原始字节已不在仓库、现存文件损坏或引用校验信息矛盾时，明确报错，不用新字体替换旧数据。

`.gitignore` 保留私有运行时目录忽略规则，补充说明内置资源应存放在受版本控制的 `assets`。README 和字体说明补充 Git 管理范围与恢复规则。私有图片和用户上传字体仍需与数据库一起备份。

## 验证

新增的前三项回归先在未修改实现上失败，再通过修复：

1. 全部字体副本被删除后，重复初始化恢复原文件，同时保留原版本、URL 和已下架状态。
2. 缺失旧版本的哈希不在仓库时拒绝恢复，不改写数据库中的原校验值。
3. 已有文件损坏时报告错误，并保留该文件原状。

另补充旧海报仍引用历史版本、当前版本已更新的场景：初始化补回旧存储键，并保留当前版本文件及版本号。
